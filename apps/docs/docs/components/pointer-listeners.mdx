# Pointer Listeners

**Pointer Listeners** runs a list of actions when the pointer moves onto a node, moves off it, presses it or releases it. It is the no-code way to make an animation react to hover and press, and it matches Rive's listeners.

Add it with **Add Component → Events & Data → Pointer Listeners (hover / press)**. The internal name is `UiListeners`.

:::note Needs a UI Button
Pointer Listeners does not detect the pointer itself. The node also needs a **UI Button**, which hit-tests the pointer. If the button should not change the node's look, set its hover and press colours to white and its scales to 1; the button then works as an invisible hit area.
:::

## Lists

The component has four action lists. Each one starts empty and has a **+ Add action** button.

| List | Runs when |
|---|---|
| **On Pointer Enter** | The pointer moves onto the node. |
| **On Pointer Exit** | The pointer leaves it. |
| **On Pointer Down** | The node is pressed. |
| **On Pointer Up** | The press ends. |

<Shot id="pointer-listeners-inspector" caption="An invisible hit shape with a UI Button, On Click running Toggle input liked, and Pointer Listeners setting hover on enter and exit." />

Each list runs once, on the frame the pointer state changes, not every frame while it holds. Within one frame the lists run in the order the events happen: enter, down, up, then the node's **On Click** actions if it was clicked, then exit.

The actions are the same as in **On Click (Events)**: show or hide nodes, set node and component fields, **Fire trigger**, **Set input**, **Toggle input (Bool)**, **Set property**, **Load scene**, **Play sound** and **Call script function**. Each action has a target, **This node** or any other node in the scene. See [Properties and bindings](../editor/properties-and-bindings.mdx#on-click-events) for the full list and value formats.

## The hover pattern

The most common setup drives a Bool state machine input from hover:

| List | Action | Value |
|---|---|---|
| On Pointer Enter | Set input `hover` | `true` |
| On Pointer Exit | Set input `hover` | `false` |

In the state machine, add a layer named `Hover` with two states, `Rest` and `Over`, and two transitions: `Rest` → `Over` when **Boolean is** `hover` is checked, and `Over` → `Rest` when it is unchecked. Mask the layer to the nodes it should animate, so hover plays on top of whatever the base layer is doing. See [State machines: layers](../editor/state-machines.mdx#layers).

Every Toasty Lite icon on this site is built this way. Move the pointer over these:

## Engine and Lite differences

| | Engine (Playground, exported games, engine embed) | Toasty Lite |
|---|---|---|
| Hit area | The UI Button node's bounds | The node's real shape path |
| Actions | All | **Set input**, **Fire trigger**, **Toggle input (Bool)**, **Set property**, **Show**, **Hide**, **Toggle visible**. **Call script function** is sent to the page as a `toasty:event`. |
| Cursor | Unchanged | `cursor: pointer` over UI Button nodes |

## Pointer Listeners or a script

Use Pointer Listeners when the response is a fixed set of actions: set an input, fire a trigger, show a node. Use a script when the response depends on game logic; a script reads the same pointer state from the UI Button's `ref.hovered`, `ref.pressed` and `ref.clicked` (see [UI components](./ui-components.mdx#reading-clicks-in-a-script)).
