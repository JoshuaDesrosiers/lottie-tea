# Components overview

A **component** is a piece of behaviour you attach to a node. A plain shape just sits there; give it a **Rigidbody 2D** and a **Box Collider 2D** and it falls and lands; add a **Light 2D** and it glows; add a **Particle System** and it sprays sparks. If you have used Unity, this is the same idea as its "Add Component" button, and most components even share Unity's names.

Components never change what a node *is*. A shape stays a shape, a text stays a text. Components stack on top, in a list, and any node can carry any number of them.

## Where components live

Select a node and look at the **Inspector**. Near the bottom is the **Components** section: one card per component, in the order they were added, and an **Add Component** button under them.

<Shot id="components-inspector-section" caption="The Inspector's Components section with a few components and the Add Component menu open" />

Each card has:

| Part | What it does |
|---|---|
| Checkbox (left of the name) | **Enabled.** Untick it to switch the component off without losing any of its settings. A disabled component is ignored by the engine exactly as if it were not there. |
| Name | The component's name (a Script shows its script's name; the shader-graph material slot shows as **Material**). |
| Trash icon | Removes the component (one undo step, like every edit). |
| Body | The component's own settings. Hover a label to see its help text. |

### Adding a component

Click **Add Component**. The menu is grouped into sections:

| Section | Components |
|---|---|
| Rendering | Camera, Light 2D, Shadow Caster 2D, Trail Renderer, Particle System, Particle Fluid 2D (goo), Particle Behaviours 2D, Goo 2D (liquid group), Anti Goo 2D, Goo Material & Glow, Goo Gloss, Particle Look (shape, blend, glow), Particle Path (flow along a path), Antialias (smooth liquid edges) |
| Effects 2D | Drop Shadow, Outline, Repeater, Mirror (symmetry), Stroke Style (dash, trim path), Pixel Snap |
| Motion | Wiggle, Parallax, Camera Shake |
| Lighting 2D | Light Flicker, Light Layers |
| Nature | Tree 2D |
| Physics 2D | Rigidbody 2D, Box Collider 2D, Circle Collider 2D, Capsule Collider 2D, Polygon Collider 2D, Hinge Joint 2D, Liquid 2D, Cloth 2D |
| Physics 3D | Rigidbody 3D, Collider 3D, Ragdoll 3D (VRM) |
| Effects 3D | Particle System 3D, Material Overrides |
| Rigging | IK Constraint 2D, Sprite Skin, Foot IK (VRM), Bone Attachment |
| Audio | Audio Source |
| Animation | Flipbook, VRM Poses (states), Humanoid Animator (mocap) |
| UI | UI Anchor, UI Stack, UI Button, UI Toggle, UI Slider, UI Scrollbar, UI Scroll View, HTML UI |
| Layout | UI Layout, UI Layout Item, UI Show When |
| Events & Data | On Click (Events), Property Binding |
| Shading | Material (Shader Graph) |
| Scripts | Every script in the project, plus **+ New Script…** |

A new component starts with sensible defaults (the engine owns them, so the Inspector never disagrees with what actually runs). Adding a **UI Button** also adds an **On Click (Events)** list, the way Unity does.

### One of each, or many?

Most components are "one per node": once a node has one, its entry in the menu is greyed out. The ones you can stack several of are:

- the four **2D colliders** (Box, Circle, Capsule, Polygon), so one body can be built from several shapes,
- **Hinge Joint 2D**,
- **Collider 3D**,
- **Anti Goo 2D** and **Goo Gloss**,
- **Scripts** (any number, even the same script twice).

### Components that appear by themselves

A few components are written for you by other Inspector controls rather than picked from the menu:

- **Sorting Layer** is what the node's **Layer** dropdown stores. See [Sorting layers](./sorting-layers.mdx).
- **Light Layers** is what a light's **Sorting layers lit** checkboxes store, and **+ Flicker** under a Light 2D adds **Light Flicker**. See [Lighting 2D](./lighting-2d.mdx).
- **Clip Options** and **Clip Fade** are what the toggles under **Clip children to this shape** store. See [Effects 2D](./effects-2d.mdx).
- **Group Fill** is what a group's **Fill** field stores. See [Effects 2D](./effects-2d.mdx).
- **Antialias** is also switched on by the **Antialias edges** checkbox on Goo 2D and Particle Fluid 2D.

You can still see, disable and remove these in the component list like any other.

### When components run

Simulation components (physics, particles, goo, liquids, cloth, trails, camera shake) run in **Playground** and in exported games. While you design, the scene stays still and light so it is easy to edit. A few exceptions help you work:

- A selected **Particle System**, **Particle Fluid 2D** or **Goo 2D** group previews live in Design while it (or something inside or above it) is selected.
- Lights, draw effects (shadow, outline, repeater, mirror, wiggle, parallax, pixel snap, stroke style) and shader materials show in Design too.
- Whole-scene **post effects** only render in Playground, the State Machine tab's preview and exports. See [Post effects](./post-effects.mdx).

### Animating component values

Every number, colour and toggle a component shows can be keyframed: in the Timeline, use **+ Property** on the node and pick the component field (for example a Light 2D's intensity or a Stroke Style's Trim End). See [Animation timeline](../editor/animation-timeline.mdx).

### Driving components from scripts

Scripts get a reference to a node with `getCompByID('id')` (the node's **Id** field in the Inspector) and then use properties and methods for the components on it:

```js
const player = getCompByID('player')
player.addImpulse(0, 340)            // Rigidbody 2D
getCompByID('torch').lightIntensity = 1.2 + Math.sin(ctx.time * 13) * 0.1  // Light 2D
getCompByID('sparks').emit(20)       // Particle System
getCompByID('camera').shake2(0.5)    // Camera Shake
getCompByID('door').playAudio()      // Audio Source
```

Each component page lists the calls that belong to it. For the full API see [Nodes and refs](../scripting/nodes-and-refs.mdx).

## Rigging components

Two 2D rigging components do not have a page of their own. Both work with **bones** (see [Nodes and layers](../editor/nodes-and-layers.mdx)).

### IK Constraint 2D

Put it on the **tip** bone of a chain (a hand, a foot, the end of a tail). Every frame, after animation and before physics, the chain of bones ending at this one bends so the tip reaches toward the target. Two-bone chains are solved exactly (arms, legs); longer chains use FABRIK (tails, tentacles).

| Field | Meaning | Range | Default |
|---|---|---|---|
| Target | The node the chain reaches for. Move it, animate it, or drive it from a script. **None (off)** disables the constraint. Bones are not offered. | any non-bone node | None |
| Chain Length | Bones the solver may bend, this one included. 2 = a limb (exact), more = FABRIK. | 1 to 32 | 2 |
| Weight | 0 = animation only, 1 = fully solved. | 0 to 1 | 1 |
| Flip bend (2-bone) | Bends a two-bone chain the other way (knee forward or back). | on/off | off |

A script moves the target like any node:

```js
// Make the arm reach for the mouse.
const target = getCompByID('hand-target')
target.x = ctx.mouseX
target.y = ctx.mouseY
```

### Sprite Skin

Unity's Sprite Skin: deforms the node's image with its bones instead of moving it rigidly, so limbs bend smoothly and tails curl. The image is cut into a grid and each grid point follows the bones near it.

| Field | Meaning | Range | Default |
|---|---|---|---|
| Grid (cols, rows) | How finely the image is cut. More = smoother bends, more vertices. | 1 to 64 each | 8 x 8 |
| Smoothness (px) | How softly influence blends between neighbouring bones. | 0.5 and up | 12 |
| Rig | Pick a root bone to bind to every bone under it. | root bones in the scene | first root bone |
| Bind to current pose | Binds (or re-binds) using the current pose as the rest pose. The card then reads "Bound to N bones". | button | |

:::tip
Pose the rig the way the art is drawn **before** pressing **Bind to current pose**. Whatever pose you bind in becomes the rest pose.
:::
