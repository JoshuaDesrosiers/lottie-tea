# Toasty Lite

Toasty Lite is the small web runtime for interactive UI animation. It plays a JSON file exported from the Toasty editor and draws it with the browser's Canvas 2D: vector shapes, images, blend modes, strokes with trim paths, path morphs, motion paths, drop shadows, keyframes and a state machine that reacts to hover, clicks and your page's data. It also draws a set of Image Effects (background, shadow, outside stroke, blur, glow, grain, gradient map, texture, clip and feather) and the scene's global texture, all of which can be animated.

In the editor, switch on **LITE** in the toolbar to only see what Lite exports. With it off, anything Lite leaves out is marked with an asterisk (*).

It is built for the parts of a website that should feel alive without becoming a project of their own: a like button, a menu icon, a theme switch, a submit button that shows its result, a download that reports progress.

| | |
|---|---|
| Size | About 25 KB of JavaScript before compression, no dependencies |
| Start-up | Instant: no WebAssembly, no WebGL context |
| Per page | As many players as you like, sharing one frame loop |
| Plays | A `.json` file from **Export → Animation → Toasty Lite (.json)** |
| Use it from | The `<toasty-lite>` element, JavaScript (`createLite`) or React (`<ToastyLite>`) |

## Lite or the engine?

Toasty ships two web runtimes. Use **Toasty Lite** for interface animation: icons, buttons, toggles, loaders and illustrations, where many small pieces share a page and each must load instantly. Use the **engine embed** for games and rich scenes that need scripts, physics, particles, audio or 3D. The engine is about 25 MB.

If your animation is made of vector shapes and is driven by a state machine, it belongs in Lite. To start from one of the ten components below, open **+ → Templates** in the editor and pick a **Lite:** template; it is added as its own scene, ready to restyle and export. See [Authoring for Lite](./authoring.mdx#start-from-a-template). The full comparison is in [Lite or engine?](./lite-vs-engine.mdx).

## Quick start

### 1. Add the runtime to your site

Copy these files into a folder your site serves. The examples on this site use `/toasty/`. This documentation site serves its own copies at `https://toastycreate.web.app/docs/toasty/`, for example `https://toastycreate.web.app/docs/toasty/an1mbyt3-lite.js`; download them from there rather than linking to them, so your site doesn't depend on ours.

| File | What it is |
|---|---|
| `an1mbyt3-lite.js` | The `<toasty-lite>` element and `createLite()`. Load this one. |
| `an1mbyt3-runtime.js` | The player. `an1mbyt3-lite.js` imports it from the same folder, so ship both. |
| `an1mbyt3-lite-react.js` | Optional. The `<ToastyLite>` React component. It also imports `an1mbyt3-runtime.js`. |
| `heart.json` | Your exported animation. The examples keep these in `/toasty/lite/`. |

### 2. Load the script and place the element

```html
<script type="module" src="/toasty/an1mbyt3-lite.js"></script>

<toasty-lite src="/toasty/lite/heart.json" ink="currentColor" style="width:40px;height:40px"></toasty-lite>
```

The element registers itself when the script loads. Give it a size: the animation scales to fit the box. `ink="currentColor"` paints the lines in the surrounding text colour, so the icon matches your light and dark themes.

### 3. Connect it to your page

The heart has a Bool input called `liked`. Put it inside a real button, let the button own the state, and pass that state to the animation:

## How the page talks to an animation

Every Lite file exposes three things to your page, all designed in the editor:

- **Inputs** belong to the state machine: Bool, Number, Enum and Trigger values that decide which state plays. Set them with `player.setInput(name, value)`, `player.fire(trigger)`, the `inputs` attribute or the React `inputs` prop.
- **Properties** are the scene's named values, bound to colours, text, positions or trim. Set them with `player.set(name, value)`, the `data` attribute or the React `data` prop. `ink` is a property.
- **Events** come back out. The player reports every state change (`toasty:state`), every property change (`toasty:prop`), and every **Call script function** action that runs on a click or hover (`toasty:event`).

## Performance and accessibility

### Performance

You can put dozens of Lite players on one page. The runtime is designed for it:

- **One frame loop.** All players on the page share a single `requestAnimationFrame` loop.
- **Repaint on change only.** A player redraws only while an animation is moving, a crossfade or hover look is easing, or after you set an input or property. An idle icon costs no drawing work.
- **Off-screen pause.** Each player watches its box with an `IntersectionObserver`. While the box is off-screen, the player skips its frames entirely, so its state machine time stands still until it scrolls back into view.
- **Sharp at any size.** The canvas tracks the box size with a `ResizeObserver` and renders at the device pixel ratio, capped at 3.
- **Cached files.** Files are fetched once per URL and shared, so ten hearts on a page download `heart.json` once.
- **Small files.** The ten components above are between 2 and 14 KB of JSON each before compression.

### Accessibility

A `<toasty-lite>` element is a `<canvas>`. Assistive technology cannot see what it draws, it cannot take keyboard focus, and its click actions only respond to a pointer. Treat it as an image inside a real control:

- **Put interactive animations inside a real `<button>`** (or link). Give the button an accessible name, either visible text or `aria-label`, and state such as `aria-pressed` or `aria-expanded`.
- **Let the button own the state.** Handle `click` on the button and pass the result to the animation with `setInput`. Add `pointer-events: none` to the `<toasty-lite>` so its own click actions don't run a second time.
- **Mirror hover with focus.** If the animation has a `hover` input, set it on `pointerenter` / `focus` and clear it on `pointerleave` / `blur`, so keyboard users see the same feedback.
- **Hide purely decorative animations** from assistive technology with `aria-hidden="true"` on the element or its wrapper. For status icons, put the status in text (a visually hidden live region, for example) rather than relying on the animation.
- **Respect reduced motion.** Check `matchMedia('(prefers-reduced-motion: reduce)')`. For decorative loops such as `loader` or `toasty`, add the `paused` attribute or show a static alternative. A paused player also stops changing state, so leave interactive icons playing.

```html
<button type="button" class="icon-button" aria-label="Open menu" aria-expanded="false">
  <toasty-lite src="/toasty/lite/menu.json" ink="currentColor" style="width:32px;height:32px;pointer-events:none"></toasty-lite>
</button>
```

In React, the `<Lite>` component used on this site takes a `label` prop that sets `role="img"` and `aria-label` on its box, and marks it `aria-hidden` when there is no label. Your own `<ToastyLite>` does not add ARIA attributes; wrap it the same way.
