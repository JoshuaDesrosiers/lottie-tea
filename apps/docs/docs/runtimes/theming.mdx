# Theming

A line icon should be drawn in the same colour as the text around it, and change when your site switches theme. Toasty Lite does this with an ordinary scene property, by convention called `ink`, that is bound to the colour of every line in the animation.

  <Lite src="menu" ink="auto" label="Menu" style={{ width: 56, height: 56 }} />

## The ink property

`ink` is a **Color** property in the scene. Each line in the icon has a **Property Binding** with the target **Stroke colour**, so setting `ink` repaints every line at once. Accent colours, such as the heart's red fill or the loader's amber arc, are not bound and stay as designed.

Eight of the ten components have `ink`. Its default is a near-black, `[0.11, 0.11, 0.13, 1]`.

| File | What `ink` colours |
|---|---|
| `heart` | The heart outline |
| `menu` | All three bars |
| `status` | The ring |
| `bell` | The bell, its knob and clapper |
| `download` | The arrow and tray |
| `copy` | Both sheets |
| `arrow` | The shaft and head |
| `loader` | The faint track (the arc is amber) |
| `theme`, `toasty` | No `ink`: their colours are part of the design |

## Setting ink

| Where | Code |
|---|---|
| HTML | `<toasty-lite ink="#2563eb">` or `<toasty-lite ink="currentColor">` |
| HTML, through data | `<toasty-lite data='{"ink": "#2563eb"}'>` |
| JavaScript | `player.set('ink', '#2563eb')` or `player.set('ink', [0.15, 0.39, 0.92, 1])` |
| React | `<ToastyLite ink="#2563eb" />`, or `<ToastyLite data={{ ink: '#2563eb' }} />` |

The `ink` **attribute** accepts CSS colours that the browser reports as `rgb()`: names, hex in any length, `rgb()`, `hsl()` and `currentColor`. The element resolves the colour through the browser and converts it for you.

:::note Wide-gamut colours
Browsers can report colours written as `oklch()`, `lab()`, `color()` or `color-mix()` in that colour space instead of `rgb()`. The element can't convert those, and leaves `ink` unchanged. If your text colours use them, set `ink` to a hex value instead, or define an sRGB fallback for the icon's `color`.
:::

A colour **property** set directly (through `data`, `player.set` or React `data`) accepts only two formats:

| Format | Example |
|---|---|
| Six-digit hex string | `'#2563eb'` |
| Array of 0 to 1 values | `[0.15, 0.39, 0.92, 1]` (alpha optional) |

Anything else, such as `'rgb(37, 99, 235)'`, `'#26e'` or `'royalblue'`, becomes white. Convert computed colours first (see [Properties](./javascript.mdx#properties)).

## Following your site's theme

`ink="currentColor"` paints the lines in the element's own text colour, read from where the element sits. An icon inside a dark card takes the card's text colour; an icon inside a link takes the link's colour.

The element then keeps following the theme. It reads the colour again whenever:

- the `class`, `data-theme` or `style` attribute of `<html>` changes, which covers most theme switchers (`<html class="dark">`, `<html data-theme="dark">`, CSS variables set on `document.documentElement.style`);
- the system preference `prefers-color-scheme` changes.

### When the colour changes some other way

`currentColor` is read again only on the changes listed above. If your theme changes in another way, set `ink` yourself:

- the theme class is on `<body>` or on a container instead of `<html>`;
- a CSS `:hover` rule changes the text colour of the surrounding link or button;
- a stylesheet is swapped, or a CSS variable changes on an element other than `<html>`.

```js
/** Re-reads an element's text colour into its ink property. */
function refreshInk(el) {
  const [r, g, b, a = 1] = getComputedStyle(el).color.match(/[\d.]+/g).map(Number)
  el.player?.set('ink', [r / 255, g / 255, b / 255, a])
}

document.body.classList.toggle('dark')
document.querySelectorAll('toasty-lite[ink="currentColor"]').forEach(refreshInk)
```

If the colour animates with a CSS transition, call `refreshInk` on `transitionend` so you read the final colour, not one from the middle of the transition.

## Brand colours and accents

`ink` is only a convention. A scene can have as many Color properties as you like, bound to strokes with **Stroke colour** or to shapes with **Fill colour**, and a page sets them all the same way. For a file of your own with an `accent` property bound to a fill:

```html
<toasty-lite
  src="/toasty/lite/your-badge.json"
  ink="currentColor"
  data='{"accent": "#e8590c"}'>
</toasty-lite>
```

The colours you don't bind are fixed in the file. Choose accents that read on both light and dark backgrounds, such as mid-tone reds, ambers and greens, as the ten components do.

## Authoring an ink-able icon

To make your own icon follow the page's colour:

1. **Add the property.** Click empty canvas so nothing is selected. In the Inspector's **Properties** section, click **+ Color**, name it `ink`, and set **Starts as** to the colour the icon should have when no page sets it, for example `[0.11, 0.11, 0.13, 1]`.
2. **Bind each line.** Select a stroke shape. Choose **Add Component → Events & Data → Property Binding**, click **+ Bind a property**, pick `ink`, and set the target to **Stroke colour**. Repeat for every stroke node: a binding colours only its own node's stroke, not its children.
3. **Bind fills if needed.** For a solid glyph, use the target **Fill colour** instead.
4. **Leave accents unbound.** Keep coloured details, such as a red badge or a green check, on their own nodes without a binding.
5. **Export** with **Export → Animation → Toasty Lite (.json)** and set `ink` from the page.

:::note Bindings and keyframes
A binding applies only while no animation track drives the same value. A line bound to `ink` follows the page in states that don't key its stroke colour, and shows the keyframed colour in states that do. The `status` ring works this way: it follows `ink` while idle and loading, and turns green or red on success or error.
:::

Test the icon with a very dark and a very light `ink` before you ship it, at the smallest size you plan to use.
