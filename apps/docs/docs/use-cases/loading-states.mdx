# Loading states

Waiting is part of every interface. A good loading state shows where the wait is (this button, this list, the whole page), keeps the layout from jumping when the content arrives, and gets out of the way once it does. The `loader` component is a chasing arc: its trim start and trim end chase each other while the arc turns. It has no inputs, so you place it, show it, and hide it. This page uses it at three scales.

## In buttons

The narrowest wait is a single action. The loader takes the place of nothing; it opens a slot next to the label while the request runs, then closes again.

### How the buttons work

- **`aria-busy="true"`** marks the button as busy. The CSS keys off the same attribute to open the loader's slot, so there's one switch for both the look and the semantics.
- **The label changes** to "Saving" or "Syncing", and a live region announces it. The icon-only Refresh button swaps its arrow icon for the loader and keeps its `aria-label`.
- **`paused`** stops the loader while its slot is closed. Removing the attribute plays it; adding it back pauses it. The `<toasty-lite>` element applies `paused` changes live without reloading.
- **Repeat clicks are ignored** while busy, instead of using `disabled`, so the button keeps keyboard focus.
- **The arc is amber and the track is a faint grey**, both fixed in the file, so the loader reads on light and dark buttons alike.

## Lists and page loads

A list that's loading should look like the list it's about to be. Skeleton rows hold the layout in place, and a loader says the wait is active. On first load, a short overlay covers the whole app until the shell is ready.

### How the list works

- **Three scales, three treatments.** The first-load overlay (`.boot`) covers the app for under a second while the shell starts. The list then shows five skeleton rows the same height as real rows, so nothing jumps when the data replaces them. Refresh and Load more each put a loader in their own button, and the rest of the page stays usable.
- **`aria-busy` on the list** tells assistive technology that the region is updating. The skeleton rows are `aria-hidden`, and a `role="status"` line says "Loading invoices..." and then "Showing 5 of 14 invoices".
- **Pausing hidden loaders.** Each button's loader starts with `paused` and only plays while its button is busy. The overlay's loader is paused once the overlay fades. A Lite player also stops drawing on its own whenever it's off-screen, because it watches its element with an `IntersectionObserver`.
- **Motion.** The skeleton shimmer stops under `prefers-reduced-motion`. Toasty Lite doesn't read that setting itself. If you want the loader still for those users, set `paused` from `matchMedia('(prefers-reduced-motion: reduce)')` and rely on the status text.

### Many loaders on one page

There are three loaders in each of the two examples above. Lite players share one animation loop, and a paused or off-screen player costs nothing per frame, so you can put a loader in every button that needs one.

## React

Both React tabs pass `paused={!busy}`; `<ToastyLite>` diffs it like any other prop. In these docs, a loader you can pause:

```jsx live
function LoaderDemo() {
  const [busy, setBusy] = React.useState(true)
  return (
    <div style={{ display: 'flex', alignItems: 'center', gap: 16 }}>
      <Lite src="loader" paused={!busy} label={busy ? 'Loading' : 'Idle'} style={{ width: 56, height: 56 }} />
      <button type="button" className="button button--secondary button--sm" onClick={() => setBusy(!busy)}>
        {busy ? 'Pause' : 'Play'}
      </button>
    </div>
  )
}
```

## Make it yours

- **Start from the template.** In the editor, **Add → Templates → Lite: Loader** opens this exact `loader` component as a new scene. Restyle it (colours, stroke widths, timing, shapes), keep the input and Property names, then use **Export → Animation → Toasty Lite (.json)** and replace `/toasty/lite/loader.json` with your file. The page code on this page works unchanged.
- **Size.** The arc reads from about 16 px up. Inside buttons, 22 to 24 px matches a 14 px label.
- **Colour.** The amber arc and the grey track are fixed in this file. The `loader` file declares an `ink` Property but nothing is bound to it, so setting `ink` has no visible effect. To recolour it, open the template (above), add a Stroke colour binding from `ink` to the `track` stroke (or change the `arc` colour), and re-export. The arc's colour isn't keyframed, so a binding on it would take effect too.
- **Speed and shape.** One `Spin` animation, 1.4 s, loops on the base layer: trim end runs ahead, trim start catches up, and trim offset and rotation keep it turning. Shorten the animation for a busier spinner.
- **Determinate progress.** When you know how far along a task is, use a ring bound to a `progress` Property instead. See [Download progress](./download-progress.mdx).
