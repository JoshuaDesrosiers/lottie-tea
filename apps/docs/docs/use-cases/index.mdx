import Link from '@docusaurus/Link'
import { useRef } from 'react'
import { Lite } from '@site/src/components/Lite'

export function UseCase({ to, src, title, children, enter, leave, inputs, data }) {
  const player = useRef(null)
  const apply = (values) => {
    if (!values || !player.current) return
    for (const [name, value] of Object.entries(values)) player.current.setInput(name, value)
  }
  return (
    <Link
      to={to}
      className="uc-card"
      onMouseEnter={() => apply(enter)}
      onMouseLeave={() => apply(leave)}
      onFocus={() => apply(enter)}
      onBlur={() => apply(leave)}
    >
      <span className="uc-stage">
        <Lite ref={player} src={src} ink="auto" inputs={inputs} data={data} style={{ width: 88, height: 88, pointerEvents: 'none' }} />
      </span>
      <span className="uc-title">{title}</span>
      <span className="uc-text">{children}</span>
    </Link>
  )
}

## What every example has in common

The examples share a small set of patterns. Once you have seen them on one page, the rest read quickly.

- **The page owns the control.** The animation sits inside a real `<button>` or `<a>`, so keyboard focus, `aria-pressed`, `aria-expanded` and form submission all work with no extra code. The canvas is decoration.
- **`pointer-events: none` on the animation.** When the page drives the animation, the canvas must not also react to clicks on its own, or the two would fight over the same input. The page forwards hover with `setInput('hover', …)` instead. The [like button](./like-button.mdx) explains this in detail.
- **`ink="currentColor"`.** Every component except `theme` and `toasty` has an `ink` Property bound to its line colour. With `ink="currentColor"` the lines take the text colour of their button and follow your light and dark themes. See [Theming](../runtimes/theming.mdx).
- **`element.player`.** Once the `toasty:ready` event has fired, the element's `.player` is the full JavaScript API: `setInput`, `fire`, `set`, `state` and `on`. See [JavaScript API](../runtimes/javascript.mdx).

## Which component goes where

| File | Inputs | Typical home |
|---|---|---|
| `heart` | `liked` Bool, `hover` Bool | Like, favourite and save buttons |
| `menu` | `open` Bool, `hover` Bool | Mobile navigation toggles, drawers |
| `theme` | `dark` Bool, `hover` Bool | Light and dark switches |
| `status` | `status` Enum: `idle`, `loading`, `success`, `error` | Submit buttons, inline validation |
| `bell` | `ring` Trigger, `unread` Bool, `hover` Bool | Notification centres, inbox badges |
| `download` | `state` Enum: `idle`, `downloading`, `done`; `hover` Bool; `progress` Property | File lists, export buttons |
| `copy` | `copy` Trigger, `hover` Bool | API keys, code snippets, share links |
| `arrow` | `hover` Bool | Calls to action, "Read more" links |
| `loader` | none | Buttons, lists and pages that are waiting |
| `toasty` | `hover` Bool, `boop` Trigger | Empty states, error pages, onboarding |

All ten files are 96 by 96 with a transparent background and no scripts, so they run in [Toasty Lite](../runtimes/lite.mdx). To build your own component in the same style, see [Authoring for Lite](../runtimes/authoring.mdx).
