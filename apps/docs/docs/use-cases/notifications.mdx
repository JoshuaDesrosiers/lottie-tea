# Notifications

A notification bell has two kinds of news to deliver: there is something unread (a steady badge) and something just arrived (a brief ring). The `bell` component keeps those apart. A Bool input, `unread`, shows or hides the red dot on its own layer, and a Trigger, `ring`, swings the bell without touching the badge. This page builds the full pattern: an app header, a dropdown list, read and unread items, and mark-all-read.

## How it works

### Two inputs for two kinds of news

| Input | Kind | Layer | What it does |
|---|---|---|---|
| `unread` | Bool | `Badge`: `Read`, `Unread` | Pops the red dot in (`true`) or shrinks it away (`false`). It stays as long as the value does. |
| `ring` | Trigger | Base: `Still`, `Ringing`, `Ringing again` | Swings the bell with a decaying rotation while the clapper knocks side to side. Each fire restarts the swing. |
| `hover` | Bool | `Hover`: `Rest`, `Over` | Tilts the bell by 10 degrees. |

Because the badge lives on its own layer, ringing never hides it and hiding it never interrupts a ring. `Ringing` and `Ringing again` point at the same animation; alternating between two states is what lets a second `ring` restart the swing while the first is still playing.

### Deriving `unread` from the data

```js
const unread = items.filter((n) => n.unread).length
bell.player?.setInput('unread', unread > 0)
```

`render()` recalculates everything from the `items` array: the list, the button's accessible name ("Notifications, 2 unread"), whether Mark all as read is enabled, and the badge. Marking one item read, marking all, or receiving a new one all end in `render()`, so the badge is never out of date.

The ring is different. It's an event, not a state, so it's fired at the moments something happens: when a notification arrives and when the panel opens.

### The button and the panel

The `bell` file has its own On Click actions: it sends an `open` event and fires `ring`. Here the button decides when to open, so the canvas has `pointer-events: none` and the page fires `ring` itself. Without that, a click on the bell would ring it twice.

The button uses `aria-expanded` and `aria-controls` to say it shows and hides the panel. The panel is a labelled region with ordinary buttons inside, so Tab moves through the items. Escape closes it and returns focus to the bell; a click outside closes it too. New arrivals are announced through a visually hidden `aria-live` region, because the badge alone says nothing to a screen reader.

### Listening instead of driving

If you place the bell without a button around it and let it handle its own clicks, listen for its event:

```js
bell.addEventListener('toasty:event', (e) => {
  if (e.detail.name === 'open') openPanel()
})
```

`open` comes from the file's On Click action **Call script function** `open`, which Lite turns into a `toasty:event`.

## Make it yours

- **Start from the template.** In the editor, **Add → Templates → Lite: Notification bell** opens this exact `bell` component as a new scene. Restyle it (colours, stroke widths, timing, shapes), keep the input and Property names, then use **Export → Animation → Toasty Lite (.json)** and replace `/toasty/lite/bell.json` with your file. The page code on this page works unchanged.
- **Counts instead of a dot.** The badge is a dot so it reads at any size. For a number, keep the dot animation and put a small `<span>` with the count over the button's corner in HTML. The animation keeps doing the motion, and HTML does the text.
- **Quieter rings.** Fire `ring` only for notifications that matter (mentions, assignments), not for every update. The badge is enough for the rest.
- **Colour.** The outline, knob and clapper follow `ink`. The red of the badge is a fill in the file.
- **Your own icon.** An envelope or a chat bubble works the same way: a base layer with a `ring` Trigger and two states that alternate, plus a `Badge` layer on an `unread` Bool. Build it in the editor and export with **Export → Animation → Toasty Lite (.json)**. See [Authoring for Lite](../runtimes/authoring.mdx).
