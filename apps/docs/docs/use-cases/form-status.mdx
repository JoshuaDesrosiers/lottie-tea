# Form status

A submit button has three jobs after it's pressed: show that the request is in flight, confirm that it worked, and say clearly when it didn't. The `status` component covers all three with one Enum input. This page wires it into a newsletter signup. The server is simulated with a timer and rejects malformed addresses, so you can see both outcomes.

## How it works

### One Enum input, four states

`status` is an Enum input with the values `idle`, `loading`, `success` and `error`. Every state has a transition to every other state, so you can set any value at any time and the icon goes straight there:

| Value | State | What it draws |
|---|---|---|
| `idle` | `Idle` | Nothing. The ring is trimmed to zero length. |
| `loading` | `Loading` (loops) | A short arc that spins once a second. |
| `success` | `Success` | The arc closes into a ring, a green disc pops, a white check draws on. |
| `error` | `Error` | The arc closes, a red disc pops, a white cross draws on, then the icon shakes. |

The ring is bound to `ink`, so with `ink="currentColor"` the idle and loading spinner takes the button's text colour. In `Success` and `Error` the animation keys the ring's colour itself (a keyframed value takes precedence over a binding in Lite), so it turns green or red as it closes, then hands over to the green or red disc with its white mark. Those read on any button.

Returning to `idle` crossfades over 0.25 s. Every other change is immediate, which is what you want when a fast server answers before the spinner has turned once.

### The button never changes its role

```html
<button class="submit" type="submit" data-status="idle">
  <toasty-lite src="/toasty/lite/status.json" ink="currentColor"></toasty-lite>
  <span class="label">Subscribe</span>
</button>
```

It's a submit button the whole time, so Enter in the field submits, and the browser handles focus. `setStatus()` changes four things together:

- `data-status` on the button, which the CSS uses to open the icon slot (it's `0` wide while idle) and set the cursor.
- The visible label: Subscribe, Subscribing, Subscribed, Try again.
- The `status` input on the icon.
- `aria-busy` on the form and `aria-invalid` on the field.

The message under the field is a `role="status"` live region, and the field points to it with `aria-describedby`. Screen reader users hear "Subscribing...", then the result, without moving focus. On an error, focus goes back to the field so the user can fix it straight away.

The button isn't `disabled` while loading. Disabling it would drop keyboard focus on the floor. The submit handler ignores extra submits instead.

### The simulated server

The `fetch` defined at the top of the script shadows the browser's for this module only. It waits 1.2 s and returns `422` with an error message when the address has no domain ending. Delete those lines and the handler sends the same request to your endpoint. The handler only relies on `res.ok` and an `{ error }` JSON body.

## React

The React tab is the same form with state in `useState`. `inputs={{ status }}` sends the new value whenever `status` changes. Here is the button on its own in these docs. Each press alternates between a success and an error:

```jsx live
function SubmitButton() {
  const [status, setStatus] = React.useState('idle')
  const [count, setCount] = React.useState(0)
  const labels = { idle: 'Save changes', loading: 'Saving', success: 'Saved', error: 'Try again' }
  function save() {
    if (status === 'loading') return
    setStatus('loading')
    setTimeout(() => {
      setStatus(count % 2 === 0 ? 'success' : 'error')
      setCount(count + 1)
      setTimeout(() => setStatus('idle'), 1800)
    }, 1200)
  }
  return (
    <button
      type="button"
      onClick={save}
      style={{ display: 'inline-flex', alignItems: 'center', gap: 8, height: 44, padding: '0 18px', border: 0, borderRadius: 10, background: 'var(--t-ink)', color: 'var(--t-bg)', font: 'inherit', fontWeight: 600, cursor: 'pointer' }}
    >
      <Lite src="status" ink="auto" inputs={{ status }} style={{ width: status === 'idle' ? 0 : 26, height: 26, transition: 'width .2s', pointerEvents: 'none' }} />
      {labels[status]}
    </button>
  )
}
```

## Make it yours

- **Start from the template.** In the editor, **Add → Templates → Lite: Form status** opens this exact `status` component as a new scene. Restyle it (colours, stroke widths, timing, shapes), keep the input and Property names, then use **Export → Animation → Toasty Lite (.json)** and replace `/toasty/lite/status.json` with your file. The page code on this page works unchanged.
- **Other forms.** Any async action fits: Save, Send invite, Pay, Upload. Keep the four values and change the labels.
- **Inline validation.** Put a second `status` icon at the end of a field and set it to `success` or `error` on blur. With no button around it, give the element `role="img"` and an `aria-label` that matches the message, or `aria-hidden="true"` if the text already says it.
- **Colours.** The idle and loading ring follows `ink`. To change the green and red, edit the `disc` fill keys and the ring's stroke colour keys in the `Success` and `Error` animations, then re-export.
- **Your own icon.** Keep an Enum input named `status` with the same four values and the page code works unchanged. See [Authoring for Lite](../runtimes/authoring.mdx).
