# Theme switch

A theme switch is a control whose result is visible everywhere at once, so the icon should land at the same moment as the page. This page builds an Appearance settings screen with two controls bound to the same value: a compact icon button in the app header and an accessible switch in the settings list. Both use the `theme` component, and both change the real theme of the page they're on.

function readTheme() {
  try {
    const saved = localStorage.getItem('theme')
    if (saved === 'light' || saved === 'dark') return saved === 'dark'
  } catch {}
  return matchMedia('(prefers-color-scheme: dark)').matches
}

export function useDarkMode() {
  const [dark, setDark] = useState(readTheme)
  useEffect(() => {
    document.documentElement.dataset.theme = dark ? 'dark' : 'light'
    try { localStorage.setItem('theme', dark ? 'dark' : 'light') } catch {}

## How it works

### The page's theme is one attribute

The example styles everything with CSS variables that change under `:root[data-theme="dark"]`. Switching the theme is one line:

```js
root.dataset.theme = dark ? 'dark' : 'light'
```

`apply()` writes the same `dark` value to every place that shows it: the attribute on `<html>`, `aria-pressed` on the header button, `aria-checked` on the switch, and the `dark` input of each theme icon. The icons, the switch and the page can't drift apart, because nothing changes them except `apply()`.

### The theme icon

`dark` is a Bool input. Setting it to `true` plays `Light` → `Dark`: the rays trim away as the ray group turns, the body morphs from a sun to a crescent moon (a path morph), and two sparkles pop in. Setting it back to `false` crossfades to `Light` over 0.3 s.

The `theme` file has no `ink` Property. Its sun is amber and its moon is a pale lavender, so it reads on both backgrounds, and in this example the moon only ever appears once the page is already dark.

### Icons that follow the theme on their own

The bell in the header has `ink="currentColor"`. It isn't in `apply()` at all. The `<toasty-lite>` element watches `class`, `data-theme` and `style` on `<html>`, as well as `prefers-color-scheme`, and re-reads its colour whenever one changes. Any line icon on your site that uses `ink="currentColor"` follows a theme switch with no extra code. See [Theming](../runtimes/theming.mdx).

### Accessibility

- The settings control is a `<button role="switch">` with `aria-checked`, labelled by the visible "Dark mode" text. Screen readers announce it as "Dark mode, switch, on".
- The header control is a toggle button with `aria-label="Dark mode"` and `aria-pressed`. Use one pattern or the other for a given control, not both.
- Both canvases have `pointer-events: none`. The buttons take the clicks and forward hover with `setInput('hover', …)`, which is what the file's own Pointer Listeners would have done.

### Saving the choice without a flash

The live example doesn't save anything, so it always starts in the docs' current theme. On your site, save the choice and apply it before the first paint with a small blocking script in `<head>`:

```html
<head>
  <meta name="color-scheme" content="light dark">
  <script>
    try {
      const saved = localStorage.getItem('theme')
      const dark = saved ? saved === 'dark' : matchMedia('(prefers-color-scheme: dark)').matches
      document.documentElement.dataset.theme = dark ? 'dark' : 'light'
    } catch {}
  </script>
</head>
```

Then add `localStorage.setItem('theme', dark ? 'dark' : 'light')` (inside a `try`) to `apply()`, and pass the starting value to the icons in HTML so they match the page as soon as they load:

```html
<toasty-lite src="/toasty/lite/theme.json" inputs='{"dark": true}'></toasty-lite>
```

The state machine always begins in its initial state, `Light`. With `dark` already `true`, it moves to `Dark` on the first frame, so a dark-mode visitor sees the 0.7 s sun-to-moon transition once as the icon appears.

## React

The React tab shows a `useDarkMode()` hook and a switch. The theme icon receives `inputs={{ dark, hover }}`. Here is the switch running in these docs. It changes only its own icon, not the docs theme:

## Make it yours

- **Start from the template.** In the editor, **Add → Templates → Lite: Light / dark switch** opens this exact `theme` component as a new scene. Restyle it (colours, stroke widths, timing, shapes), keep the input and Property names, then use **Export → Animation → Toasty Lite (.json)** and replace `/toasty/lite/theme.json` with your file. The page code on this page works unchanged.
- **Sizes.** The icon scales with its element. In a 28 px thumb the rays still read; below about 20 px, drop the rays in your own version.
- **Colours.** The sun, moon and sparkle colours are fill colours in the file. Change them in the editor, or add a Color Property with a Fill colour binding so the page can set them.
- **Three-way choice.** For Light / Dark / System, use a radio group. Keep one `theme` icon showing the resolved value: `setInput('dark', resolvedIsDark)`.
- **Your own icon.** The file is a `body` shape with a path morph between two shapes, a `rays` group whose strokes trim away, and a state machine on a `dark` Bool. Rebuild it in the editor with your own shapes, keep the input name, and export with **Export → Animation → Toasty Lite (.json)**. See [Authoring for Lite](../runtimes/authoring.mdx).
