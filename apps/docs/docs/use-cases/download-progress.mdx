# Download progress

A download button should answer three questions without a second element: can I click this, how far along is it, and is it finished. The `download` component does that with an Enum input for the phase and a `progress` Property, a number from 0 to 1 that's bound to the trim end of its ring. This page builds a shared-files list where every row has its own button and its own progress, all running at once.

  return new Promise((resolve, reject) => {
    let loaded = 0
    const tick = () => {

## How it works

### A phase and a number

| Name | Kind | Values | What it does |
|---|---|---|---|
| `state` | Enum input | `idle`, `downloading`, `done` | `Idle` rests. `Downloading` loops a gentle bob of the arrow. `Done` drops the arrow and tray away, draws a green check, and turns the ring green. |
| `progress` | Number Property | `0` to `1` | Bound to the ring's trim end. `0.42` draws 42 % of the circle. |
| `hover` | Bool input | | Widens the tray a little, on its own `Hover` layer. |
| `ink` | Color Property | | The arrow and tray. |

The split matters. The state machine decides what the icon *is doing*; the Property says *how far* it got. You can stream hundreds of progress updates a second through `set('progress', …)` without ever touching the state machine, and the player repaints at most once per frame.

```js
icon.player?.setInput('state', state)   // phase: idle, downloading, done
icon.player?.set('progress', progress)  // 0..1, straight onto the ring
```

### Each row owns its state

The script loops over the rows and gives each one its own `state`, `progress` and `AbortController` in a closure. Any number of `<toasty-lite>` elements can run on one page. They share a single `requestAnimationFrame` loop and only repaint when something changes, so four rings streaming at once cost about the same as one.

### The button

- Its `aria-label` says what a click will do next: "Download Brand assets.zip", "Cancel download of Brand assets.zip", or "Downloaded Brand assets.zip".
- The meta line under the file name shows the percentage and bytes for sighted users. A separate live region announces only the start, the finish and a cancellation, so a screen reader isn't flooded with percentages.
- The canvas has `pointer-events: none`. The `download` file's own click sends a `download` event (useful when it stands alone, see below), but here the button handles clicks.

### Streaming a real download

Swap `simulateDownload` for this. It reads the response body as a stream and reports progress from `Content-Length`:

```js
async function download(url, signal, onProgress) {
  const res = await fetch(url, { signal })
  if (!res.ok) throw new Error('HTTP ' + res.status)
  const total = Number(res.headers.get('Content-Length')) || 0
  const reader = res.body.getReader()
  const chunks = []
  let loaded = 0
  for (;;) {
    const { done, value } = await reader.read()
    if (done) break
    chunks.push(value)
    loaded += value.length
    if (total) onProgress(loaded / total)
  }
  return new Blob(chunks)
}

function saveBlob(blob, name) {
  const a = document.createElement('a')
  a.href = URL.createObjectURL(blob)
  a.download = name
  a.click()
  setTimeout(() => URL.revokeObjectURL(a.href), 1000)
}
```

If the server doesn't send `Content-Length` (some compressed responses don't), there is no total to divide by. Leave `progress` at a small value such as `0.15` and rely on the `Downloading` bob to show activity.

### Standalone: listen for the event

With no button around it, the icon's own click sends a `download` event:

```js
icon.addEventListener('toasty:event', (e) => {
  if (e.detail.name === 'download') startDownload()
})
```

## React

`state` goes in `inputs` and `progress` goes in `data`. Both are diffed, so each `setProgress` sends one number to the player. In these docs, with a slider standing in for the network:

```jsx live
function ProgressDemo() {
  const [progress, setProgress] = React.useState(0.35)
  const state = progress >= 1 ? 'done' : progress > 0 ? 'downloading' : 'idle'
  return (
    <div style={{ display: 'flex', alignItems: 'center', gap: 16, flexWrap: 'wrap' }}>
      <Lite src="download" ink="auto" inputs={{ state }} data={{ progress }} label={'Download ' + Math.round(progress * 100) + '% complete'} style={{ width: 72, height: 72 }} />
      <input type="range" min="0" max="1" step="0.01" value={progress} onChange={(e) => setProgress(Number(e.target.value))} aria-label="Progress" />
      <span style={{ fontVariantNumeric: 'tabular-nums' }}>{Math.round(progress * 100)}% · {state}</span>
    </div>
  )
}
```

## Make it yours

- **Start from the template.** In the editor, **Add → Templates → Lite: Download + progress** opens this exact `download` component as a new scene. Restyle it (colours, stroke widths, timing, shapes), keep the input and Property names, then use **Export → Animation → Toasty Lite (.json)** and replace `/toasty/lite/download.json` with your file. The page code on this page works unchanged.
- **Uploads.** The page code is the same for uploads: feed `progress` from `XMLHttpRequest`'s `upload.onprogress`, or from any library that reports progress. For an arrow that points up, make your own variant of the icon (see the last point).
- **Colours.** The arrow and tray follow `ink`. The amber ring and the green finish are colour keys in the `Idle`, `Downloading` and `Done` animations; change them in the editor.
- **Reset after done.** For a button that can be used again (Export CSV), set `state` back to `idle` and `progress` to `0` a couple of seconds after `done`. The return crossfades over 0.3 s.
- **Your own icon.** Any shape works with the same page code, as long as it has an Enum input named `state` with the three values and a Number Property named `progress`. Bind `progress` to a stroke's trim end with a Property Binding, then export with **Export → Animation → Toasty Lite (.json)**. See [Authoring for Lite](../runtimes/authoring.mdx).
