# Like button

A like button is the smallest place where motion pays for itself. The heart confirms the tap before the server answers, and the burst makes a one-pixel state change feel deliberate. This page puts the `heart` component inside a real `<button>` in a social post, updates the count immediately, saves in the background and rolls back if the save fails.

import { ToastyLite } from './toasty/an1mbyt3-lite-react.js'

export function LikeButton({ postId, initialCount, initialLiked = false, ink = '#18181b' }) {
  const [liked, setLiked] = useState(initialLiked)
  const [count, setCount] = useState(initialCount)
  const [hover, setHover] = useState(false)

  async function toggle() {
    const next = !liked
    setLiked(next)
    setCount((c) => c + (next ? 1 : -1))
    const res = await fetch('/api/posts/' + postId + '/like', { method: next ? 'PUT' : 'DELETE' })
    if (!res.ok) {
      setLiked(!next)
      setCount((c) => c + (next ? -1 : 1))
    }
  }

  return (
    <button
      type="button"
      className="like"
      aria-pressed={liked}
      onClick={toggle}
      onPointerEnter={() => setHover(true)}
      onPointerLeave={() => setHover(false)}
      onFocus={() => setHover(true)}
      onBlur={() => setHover(false)}

## How it works

### The button is the control, the heart is the picture

```html
<button class="like" type="button" aria-pressed="false">
  <toasty-lite src="/toasty/lite/heart.json" ink="currentColor"></toasty-lite>
  <span class="visually-hidden">Like</span>
  <span class="count">1,284</span>
</button>
```

The `<toasty-lite>` element draws into a `<canvas>`. A canvas has no role, no label and no keyboard behaviour, so it never stands in for the control. Wrapping it in a `<button>` gives you all of that for free:

- **Focus and keys.** Tab reaches it, and Space or Enter clicks it.
- **State.** `aria-pressed` tells screen readers whether the post is liked. The script keeps it in sync.
- **A name.** The visually hidden "Like" plus the visible count give the accessible name "Like 1,284".
- **A bigger target.** The whole pill is clickable, not just the heart's outline.

### Why the canvas has `pointer-events: none`

```css
.like toasty-lite { width: 40px; height: 40px; margin: -8px -6px -8px -10px; pointer-events: none; }
```

The `heart` file has its own UI Button with an On Click action, Toggle Input `liked`. That's what makes it work as a standalone icon. Inside your button, though, the page already decides the value of `liked`. If the canvas also received the click, the runtime would toggle `liked` on its next frame, right after your handler set it, and the heart would flip back.

`pointer-events: none` hands every pointer event to the button. The page then owns the value and forwards hover itself:

```js
button.addEventListener('pointerenter', () => heart.player?.setInput('hover', true))
button.addEventListener('pointerleave', () => heart.player?.setInput('hover', false))
```

The negative margin lets the 40 px canvas keep room for the burst rays without pushing the count away.

### Setting the input

```js
heart.player?.setInput('liked', liked)
```

`liked` is a Bool input. Setting it to `true` moves the base layer from `Unliked` to `Liked`: the fill scales 0 → 1.22 → 1 and eight trim-path rays and a ring burst out. Setting it to `false` crossfades back to `Unliked` over 0.18 s. Setting the same value twice does nothing, so `render()` is safe to call as often as you like.

`heart.player` is `null` until the file has loaded, which is why the call uses `?.` and why `render()` also runs on `toasty:ready`.

### Optimistic saving

The click handler updates the count and the heart before it calls the server, so the response time never shows. If the save fails, and the user hasn't clicked again in the meantime (`liked === wanted`), it reverses both and says so in a `role="status"` region that screen readers announce.

### The inputs and states used

| Name | Kind | Set by |
|---|---|---|
| `liked` | Bool input | The page, on click |
| `hover` | Bool input | The page, on pointer enter / leave and focus / blur |
| `ink` | Color Property | `ink="currentColor"`: the button's text colour, so the outline follows the theme |
| `Unliked`, `Liked` | Base layer states | The `liked` input |
| `Rest`, `Over` | `Hover` layer states | The `hover` input (the heart scales to 1.12) |

## Alternative: let the heart own the state

For a standalone icon with no count and no button around it, you can let the animation toggle itself and listen for the result. Leave pointer events on, and read the base layer's state:

```html
<toasty-lite id="save" src="/toasty/lite/heart.json" ink="currentColor"
  role="img" aria-label="Save to favourites" style="width:48px;height:48px"></toasty-lite>

<script type="module">
  document.querySelector('#save').addEventListener('toasty:state', (e) => {
    const { layer, state } = e.detail
    if (layer !== null) return // ignore the Hover layer
    if (state === 'Liked') saveFavourite()
    if (state === 'Unliked') removeFavourite()
  })
</script>
```

This is shorter, but the canvas is not focusable, so keyboard users can't reach it. Prefer the button version for anything a user needs to act on.

## React

The React tab above is the same component with `<ToastyLite>`. Props are diffed, so passing a fresh `inputs={{ liked, hover }}` object on every render only sends the values that changed. Its `ink` prop takes any CSS colour string (`'#18181b'`, `'rgb(24 24 27)'`, a named colour) and sets the file's `ink` Property; changing it recolours the outline live.

Inside these docs the same thing is available as `<Lite>`. Edit the code and the preview updates:

```jsx live
function LikeButton() {
  const [liked, setLiked] = React.useState(false)
  const [hover, setHover] = React.useState(false)
  const count = 1284 + (liked ? 1 : 0)
  return (
    <button
      type="button"
      aria-pressed={liked}
      onClick={() => setLiked(!liked)}
      onPointerEnter={() => setHover(true)}
      onPointerLeave={() => setHover(false)}
      style={{ display: 'inline-flex', alignItems: 'center', gap: 6, height: 40, padding: '0 14px', border: '1px solid var(--t-line)', borderRadius: 999, background: 'transparent', color: 'inherit', font: 'inherit', cursor: 'pointer' }}
    >
      <Lite src="heart" ink="auto" inputs={{ liked, hover }} style={{ width: 40, height: 40, margin: '-8px -6px -8px -10px', pointerEvents: 'none' }} />
      <span style={{ fontVariantNumeric: 'tabular-nums' }}>{count.toLocaleString('en-US')}</span>
    </button>
  )
}
```

## Make it yours

- **Start from the template.** In the editor, **Add → Templates → Lite: Like heart** opens this exact `heart` component as a new scene. Restyle it (colours, stroke widths, timing, shapes), keep the input and Property names, then use **Export → Animation → Toasty Lite (.json)** and replace `/toasty/lite/heart.json` with your file. The page code on this page works unchanged.
- **Colour.** The outline uses the `ink` Property, so `ink="currentColor"` plus your button's `color` is all you need for brand or theme colours. The red fill and the red and amber rays are fixed colours in the file.
- **Size.** Size the element with CSS. The scene is 96 by 96 and scales without blurring, because Lite redraws at the device pixel ratio.
- **A different shape.** To make a star, a bookmark or a thumbs-up with the same behaviour, start from the template and swap the shapes, or build the structure from scratch: a `fill` shape that starts at scale 0, an `outline` stroke bound to `ink` with a Stroke colour binding, ray strokes animated with trim start and trim end, and a state machine with a `liked` Bool and `Unliked` / `Liked` states. Add a `hover` Bool with a second layer, set by Pointer Listeners. Then use **Export → Animation → Toasty Lite (.json)**. The export lists anything Lite can't play. [Authoring for Lite](../runtimes/authoring.mdx) walks through it.
