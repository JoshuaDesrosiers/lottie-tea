# Demos

The editor includes a set of built-in demo scenes under **+ → Demos** in the top toolbar: small games and single-feature labs for physics, particles, lighting, UI, 3D and more. Each one is built from the same nodes, components, state machines and scripts you use yourself, so you can open it and read how it works.

These docs do not walk through the built-in demos. For worked examples, use the [use cases](../use-cases/index.mdx), the two documented [games](../games/index.mdx), and the [courses](../courses/index.mdx).

## What loading a demo does

- Most demos **add their own scenes** to the document you have open, switch to the first one, and start **Playground**. Press **Design** to stop and inspect it.
- A few build into the scene you have open instead of adding a new one.
- Demos with large assets (images, 3D models, avatars) take a moment to load.

:::caution Demos and your project
A demo's scenes become part of the document like any scene you made. If a project is open, they are **autosaved into it**. When you are done, delete the demo's scenes from the **Scene** picker (trash button), or explore demos in a separate project. See [Projects and saving](../getting-started/projects-and-saving.mdx#replacing-the-document).
:::

## How to study a demo

1. Load it and play it.
2. Press **Design**. Use the **Scene** picker to see every scene it added.
3. Select nodes in the **Layers** panel and read their components in the **Inspector**.
4. Open the **State Machine** tab. Most demos run their logic from a Programmable State: double-click a state with a ▸ badge to read its code, or switch to **Code** mode to browse every scene script.
5. Change something and press **Playground** again.
