# 1. Project setup

**Goal:** a project with an empty `Level 1` scene that's sized, lit and wired for the script you'll write in lesson 3.

**What you'll learn**

- What you'll build over the seven lessons, and which real demo it borrows from.
- The art you need and how it must be laid out.
- Scene size, Physics 2D gravity and a pixel-perfect Main Camera.
- Creating the state machine and the shared script file every level will run.

## What you'll build

A side-scrolling platformer: a ninja runs and jumps across tiled platforms, collects spinning coins for points, hears little synthesized sounds, and walks through a door into a second level. At the end you'll export it as a web page anyone can play.

Toasty ships a demo built from the same ninja sprites: **Ninja Adventure** (**+ → Demos → Ninja Adventure** in the editor). It's a top-down adventure rather than a platformer, but this course reuses its script patterns line for line: sprite frames named `sheet index`, game state in `ctx.globals`, a smoothed and clamped follow camera, pickups, a heads-up display, and two scenes joined with `ctx.loadScene`. Here it is, running:

Where Ninja Adventure moves its characters by hand, your platformer uses **Physics 2D** (Rigidbody 2D and colliders), the same way the built-in **Physics Playground** demo does. You'll see both sources quoted as you go.

## The art you need

Any pixel-art pack works if the sheets are laid out the same way. The free (CC0) **Ninja Adventure** asset pack by Pixel-boy and AAA, which the demo's art comes from, fits exactly. You need:

| File | Layout | Used for |
|---|---|---|
| `ninja_walk.png` | 4 columns × 4 rows of equal cells. Columns are the facing: **0 down, 1 up, 2 left, 3 right**. Rows are the 4 walk frames. | Running, and the pose in the air. |
| `ninja_idle.png` | Same layout, 4 idle (breathing) frames. | Standing still. |
| `coin.png` | One row of 4 equal cells. | The spinning coin. |
| A tileset, e.g. `tileset_floor.png` | A grid of 16 × 16 tiles. | The ground. |

Rename your files to these names. The script finds frames by name, so `ninja_walk 7` must mean "walk sheet, frame 7".

:::tip Different art?
A side-on platformer sheet usually has only left/right columns. That's fine: you'll just change one line in lesson 4 that picks the column. The layout table above is what the course code expects as written.
:::

## Step 1: the scene

1. Create a project: **File → New Project…**. (In the browser without a project folder you can still follow along; see [Projects and saving](../../getting-started/projects-and-saving.mdx).)
2. Open the **Scene** dropdown in the toolbar, rename the scene (pencil icon) to `Level 1`. Use exactly this name: the script looks levels up by scene name.
3. Click empty canvas so nothing is selected. In the Inspector's **Canvas** section:
   - **Size**: **W** `480`, **H** `270`. A 16:9 view that's 30 × 17 tiles of 16 px.
   - **Gravity**: leave the default (**X** `0`, **Y** `-313.92`). That's Unity's -9.81 m/s² at 32 pixels per metre. **+Y is up** in Toasty, so gravity is negative.

## Step 2: a pixel-perfect camera

1. **+** (the **Add** button) → **Camera**.
2. In the Inspector, set its **Id** to `camera`. The script will move it.
3. On its **Camera** component:
   - tick **Main Camera (Playground views through this)**;
   - set **Background** to a dusk blue such as `#1d2440`;
   - tick **Pixel Perfect**, so 1 world unit is exactly 1 art pixel and sprites scale in whole pixels.

## Step 3: the state machine and the script file

Scripts run inside a **Programmable State**. Every level gets a one-state machine running one shared file.

1. Open the **Timeline** (left icon rail). Open its animation dropdown and pick **New Animation**. (A state machine needs an animation to exist, even though a programmable state doesn't play it.)
2. Open the **State Machine** panel. In its dropdown pick **New State Machine**, name it `Game`, press **Create**. It has one state, `State 1`.
3. Select `State 1` and tick **Programmable State** under **Program**.
4. Switch to **Code** mode. In **Files**, click **+js**, name it `Scripts/ninja.js`, press Enter. Paste this placeholder:

```js title="Scripts/ninja.js"
// The ninja platformer. Every level scene runs this one file.
// Lesson 3 replaces this with the real thing.
const player = getCompByID('player')
if (!player) {
  // Printed once per second-ish so the Console doesn't flood.
  if (Math.floor(ctx.time) !== Math.floor(ctx.time - ctx.deltaSeconds)) print('No node with Id "player" yet in', ctx.scene)
}
```

5. Back in **Design**, double-click `State 1` in the State Machine panel, open the **Code** tab, and in **Runs** pick `Scripts/ninja.js`.
6. Press **Playground**, then open the Console. You should see the "No node with Id player" line about once a second. Leave Playground.

## How it works

- **Why one script file?** Each scene has its own state machine, but the game logic is the same everywhere. A project file run by every level (`@file:Scripts/ninja.js` under the hood) means a fix in one place fixes every level. The script tells levels apart with `ctx.scene`. Ninja Adventure does the same: one script, a `SCENES` table keyed by scene name.
- **`print`** writes to the Console, like `console.log`. Both work in scripts. See [Debugging](../../scripting/debugging.mdx).
- **`ctx.time`** is the seconds since the state was entered, and `ctx.deltaSeconds` the length of this frame. The `Math.floor` comparison is true on the one frame where `ctx.time` crosses a whole second.

## Check your work

- The scene is called `Level 1`, sized 480 × 270, with default gravity.
- A Camera with Id `camera` is the Main Camera.
- The `Game` state machine has one programmable state running `Scripts/ninja.js`.
- In Playground the Console prints the placeholder message.
