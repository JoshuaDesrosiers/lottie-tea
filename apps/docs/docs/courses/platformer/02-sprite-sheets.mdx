# 2. Sprite sheets and the Sprite Editor

**Goal:** every animation frame available as its own named image, and the ninja standing in the scene.

**What you'll learn**

- Importing images and setting **Filter Mode** for pixel art.
- The **Sprite Editor**: **Cell size**, **Cell count** and **Automatic** slicing.
- How sliced frames are named, and why the names matter to scripts.
- Placing an image from Resources as a sprite node.
- Listing frames from a script with `ctx.images`.

## Step 1: import the sheets

1. **+** → **Import** → **Image…**, and pick `ninja_walk.png`. Repeat for `ninja_idle.png` and `coin.png`.
2. Open **Resources** (left icon rail). The three images are listed there.

## Step 2: crisp pixels

Select `ninja_walk.png` in Resources. The Inspector shows the image's import settings. Set **Filter Mode** to **Nearest**. Do the same for the other two.

`Linear` filtering blends neighbouring pixels when a sprite is scaled or sits between pixels, which blurs pixel art. `Nearest` keeps every pixel a hard square.

## Step 3: slice the walk sheet

1. With `ninja_walk.png` still selected, click **Sprite Editor…** in the Inspector. The sheet opens over the editor with a grid drawn on it.
2. Choose the **Cell size** tab. Set **Cell width** and **Cell height** to your sheet's cell size: the sheet's width divided by 4 (32 for a 128 × 128 sheet, 16 for a 64 × 64 one). The Sprite Editor shows the sheet's size next to its name.
   - Alternatively, use **Cell count** with **Columns** `4` and **Rows** `4`. Toasty works out the cell size for you.
3. **Untick Skip empty cells.** If any cell happened to be blank and got skipped, every later frame number would shift by one and the script would show the wrong poses.
4. Leave **Name** as `ninja_walk` and set **Frame time (ms)** to `125` (8 frames a second).
5. Click **Slice 16 sprites**.

<Shot id="platformer-sprite-editor" caption="The Sprite Editor slicing ninja_walk.png into a 4 x 4 grid, Cell size tab, Skip empty cells unticked." />

Resources now shows a sprite group called `ninja_walk` holding sixteen frames named `ninja_walk 0` to `ninja_walk 15`, numbered left to right, top to bottom.

Slice the other two the same way:

| Sheet | Tab | Settings | Result |
|---|---|---|---|
| `ninja_idle.png` | Cell count | Columns 4, Rows 4, Skip empty cells off | `ninja_idle 0` … `ninja_idle 15` |
| `coin.png` | Cell count | Columns 4, Rows 1, Skip empty cells off | `coin 0` … `coin 3` |

:::info The three slicing modes
- **Cell size**: fixed-size cells, with **Offset X/Y** (where the grid starts) and **Padding X/Y** (gaps between cells) for sheets with margins.
- **Cell count**: columns × rows fitted to the sheet.
- **Automatic**: finds every separate sprite by its transparent edges (**Alpha threshold**, **Min size (px)**, **Merge gap (px)**, then **Detect sprites**). Great for packed sheets with uneven sprites, but the frame order is reading order, so check the numbers.

In every mode you can click a slice in the preview to leave it out. More in the [Sprite Editor](../../editor/sprite-editor.mdx) guide.
:::

## Step 4: how frames are numbered

The walk sheet's columns are facings and its rows are frames, so frame number `n` is:

```
index = row * 4 + column        // column: 0 down, 1 up, 2 left, 3 right
```

| | col 0 (down) | col 1 (up) | col 2 (left) | col 3 (right) |
|---|---|---|---|---|
| row 0 | 0 | 1 | 2 | 3 |
| row 1 | 4 | 5 | 6 | 7 |
| row 2 | 8 | 9 | 10 | 11 |
| row 3 | 12 | 13 | 14 | 15 |

So a ninja running right cycles through `ninja_walk 3`, `7`, `11`, `15`. Ninja Adventure's script uses exactly this formula:

```js
// From the Ninja Adventure demo: "column = facing, row = frame".
pose = 'ninja_walk ' + ((Math.floor(G.clock * WALK_FPS) % 4) * 4 + G.facing)
```

## Step 5: place the ninja

1. In **Resources**, drag the frame `ninja_walk 3` (facing right) onto the canvas. It becomes an image node.
2. Set its **Id** to `player`.
3. Put it at about **X** `-180`, **Y** `-40`.

A side note on `ninja_walk 3`: any frame works as the starting picture, because the script will choose the frame every frame from lesson 4 on.

## Step 6: a coin

1. Drag `coin 0` from Resources onto the canvas, at about **X** `-80`, **Y** `-60`.
2. In **Classes**, add the class `coin`. Scripts find every coin with `getCompByClass('coin')`, so you'll never need to name coins one by one.
3. Leave its **Id** as it is. Toasty gives every node a unique Id like `shape(12)`, and the script uses it to remember which coins you've collected.

You'll add more coins in lesson 5.

## Step 7: check the frames from a script

Replace `Scripts/ninja.js` (in **Code** mode) with this short test:

```js title="Scripts/ninja.js (test)"
// Lists every image the scene knows, once, then shows the ninja
// running in place to prove the frame names are right.
const G = ctx.globals
if (!G.listed) {
  G.listed = true
  // ctx.images: every image asset in the project, as { id, name }.
  print(ctx.images.map((img) => img.name).join(', '))
  G.frames = {}
  for (const img of ctx.images) G.frames[img.name] = img.id
}
const player = getCompByID('player')
if (player) {
  // Right-facing column (3), 8 frames a second.
  const frame = (Math.floor(ctx.time * 8) % 4) * 4 + 3
  const id = G.frames['ninja_walk ' + frame]
  // ref.image swaps which picture an image node draws.
  if (id) player.image = id
}
```

## How it works

- **`ctx.images`** lists every image asset as `{ id, name }`. Names come from the Sprite Editor (`<Name> <n>`). The script builds a lookup table once, in `ctx.globals`, so later frames don't search the list.
- **`player.image = id`** swaps the picture an image node shows. It's the standard way to animate a sprite from code: no animation clips, just pick the frame you want this frame. The demo's `setImage` helper adds one trick you'll use in lesson 4: only write when the frame actually changes, since every write is a call into the engine.
- **`ctx.globals`** is a plain object that lives for the whole play session, across frames and scene switches. Anything you want to remember goes in it.

:::note Sprite groups as flipbooks
Slicing also groups the frames as one sprite group that can play on its own as a flipbook at the **Frame time** you chose. The platformer doesn't use that, because the right frame depends on what the ninja is doing, but it's the quickest way to get a looping decoration like a torch. See [Images and sprites](../../editor/images-and-sprites.mdx).
:::

## Check your work

- Resources shows three sprite groups: `ninja_walk` (16), `ninja_idle` (16) and `coin` (4).
- In Playground, the Console lists frame names including `ninja_walk 0` … `ninja_walk 15`, and the ninja runs on the spot facing right.
- If the ninja shows the wrong direction, your sheet's columns are in a different order. Note which column is "right" and use it in place of `3`.
