# 4. Export and embed in React

**Goal:** the like button running inside your own React app, showing a count the app controls and reporting clicks back to it.

**What you'll learn**

- **Export → Game → Website embed (React / JS)** and what's in the folder it makes.
- Where the files go in a Vite (or Next.js / CRA) project.
- `An1Player`'s `data` and `onEvent` props.

## Step 1: export

1. In the editor, make sure the `Like` scene is the active one (the export starts on the active scene).
2. Click the **Export** button in the toolbar → **Game → Website embed (React / JS)**.
3. Pick a folder. The editor writes a new folder inside it called `Like-embed`.

What you get:

```
Like-embed/
  README.md                 what it is + quick start
  GUIDE.md                  step-by-step guide for people
  AGENTS.md                 the full API + this game's surface, for AI coding assistants
  an1mbyt3.json             this game's scenes / inputs / events as data
  example.html              a working test page
  src/an1mbyt3/             code you import
    an1mbyt3-embed.js (+ .d.ts)
    an1mbyt3-react.js (+ .d.ts)
    an1mbyt3-engine.js
  public/an1mbyt3/          static files your site serves
    game.teab               the scene
    an1mbyt3_wasm_bg.wasm   the engine
```

See [Export for the web](../../embedding/export-for-web.mdx) for every file in detail.

## Step 2: copy it into your app

If you don't have a React app yet:

```bash
npm create vite@latest like-demo -- --template react-ts
cd like-demo
npm install
```

Then copy the two halves across:

- `Like-embed/src/an1mbyt3/` → `like-demo/src/an1mbyt3/`
- `Like-embed/public/an1mbyt3/` → `like-demo/public/an1mbyt3/`

Your site now serves the scene at `/an1mbyt3/game.teab`, with the engine right next to it.

:::caution Keep them together
The `.js` files, `game.teab` and the `.wasm` engine come from one export and belong together. When you change the scene, export again and replace **all** of them.
:::

## Step 3: show it

Create `src/LikeButton.tsx`:

```tsx title="src/LikeButton.tsx"
import { useState } from 'react'
import { An1Player } from './an1mbyt3/an1mbyt3-react.js'

/** The Toasty like button, controlled by React state. */
export function LikeButton({ initialCount = 128, initialLiked = false }) {
  // React owns the values; the scene displays them.
  const [count, setCount] = useState(initialCount)
  const [liked, setLiked] = useState(initialLiked)

  return (
    <div style={{ width: 240 }}>
      <An1Player
        game="/an1mbyt3/game.teab"
        // The box must have a height, or the player is 0 px tall.
        style={{ width: 240, height: 240 }}
        // Written into the scene Properties `count` and `liked`. Only keys
        // whose value changed are sent, so this is cheap on every render.
        data={{ count, liked }}
        // The scene's ctx.emit('like', { liked, count }) arrives here.
        onEvent={(e) => {
          if (e.name !== 'like') return
          const payload = e.payload as { liked: boolean; count: number }
          setLiked(payload.liked)
          setCount(payload.count)
        }}
      />
      <p>React thinks: {liked ? 'liked' : 'not liked'}, {count} likes</p>
    </div>
  )
}
```

Use it in `src/App.tsx`:

```tsx title="src/App.tsx"
import { LikeButton } from './LikeButton'

export default function App() {
  return (
    <main style={{ padding: 32 }}>
      <h1>My post</h1>
      <LikeButton initialCount={1204} />
    </main>
  )
}
```

Run `npm run dev` and open the page.

## Try it live

This is the same component, running against the finished `like-button.teab`. Edit the code: change the starting count, or start it liked.

```jsx live
function LikeButtonDemo() {
  const [count, setCount] = React.useState(1204)
  const [liked, setLiked] = React.useState(false)
  return (
    <div>
      <ToastyPlayer
        game="/games/like-button.teab"
        style={{ width: 240, height: 240 }}
        data={{ count, liked }}
        onEvent={(e) => {
          if (e.name !== 'like') return
          setLiked(e.payload.liked)
          setCount(e.payload.count)
        }}
      />
      <p>React thinks: {liked ? 'liked' : 'not liked'}, {count} likes</p>
      <button onClick={() => setCount((c) => c + 100)}>Someone else liked it 100 times</button>
    </div>
  )
}
```

## How it works

### `data`: page to scene

`data={{ count, liked }}` writes each key into `ctx.data` for scripts **and** into the scene Property of the same name. So `count` lands in the `count` Property, the Property Binding updates the label, and the script's next frame sees the new value. React only sends keys whose value changed (compared with `Object.is`), so passing `data` on every render costs nothing.

The "Someone else liked it" button shows the direction page → scene: the label jumps by 100 with no scene code involved.

### `onEvent`: scene to page

Every `ctx.emit(name, payload)` in the scene calls `onEvent({ name, payload })`. The handler copies the new values into React state.

### Why the values don't fight

After a click the scene has already changed `liked` and `count` itself. React then sets the same values and passes them back through `data`. Since they're equal to what the scene already has, nothing visible happens. Sending a value a Property already holds is a no-op. Data are values, not commands.

:::tip The game also reports Property changes
Instead of `onEvent`, you could listen with `onPropChange={(e) => …}`, which fires whenever the *scene* changes a Property (`{ name: 'count', value: 129 }`). The event is nicer here because one `like` carries both values and only fires on real clicks.
:::

## Check your work

- The heart appears in your app at 240 × 240 and the label shows the count you passed in (`1204`), not the scene's default (`128`).
- Clicking the heart updates the "React thinks" line.
- Changing `initialCount` and reloading shows the new count.
- If you see nothing, check the browser's Network tab for a 404 on `/an1mbyt3/game.teab` or the `.wasm`, and that the box has a height. [Troubleshooting](../../embedding/troubleshooting.mdx) covers the rest.
