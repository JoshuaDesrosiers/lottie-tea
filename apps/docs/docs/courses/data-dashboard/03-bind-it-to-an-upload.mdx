# 3. Bind it to an upload

**Goal:** the ring shows a real upload's progress, says "Done" when the server has the file, and the page reacts.

**What you'll learn**

- Getting upload progress in the browser (`XMLHttpRequest.upload.onprogress`).
- Feeding a fast-changing value into `data` (it's cheap).
- Using the ring's `done` event and `Done` state in the page.
- Changing `label` and `color` for errors.

## Upload progress in the browser

`fetch` can't report upload progress, but `XMLHttpRequest` can. This small hook wraps it:

```tsx title="src/useUpload.ts"
import { useCallback, useRef, useState } from 'react'

export type UploadStatus = 'idle' | 'uploading' | 'done' | 'error'

/** Uploads one file to `url` with progress (0..1). */
export function useUpload(url: string) {
  const [progress, setProgress] = useState(0)
  const [status, setStatus] = useState<UploadStatus>('idle')
  const xhrRef = useRef<XMLHttpRequest | null>(null)

  const start = useCallback(
    (file: File) => {
      xhrRef.current?.abort()
      const xhr = new XMLHttpRequest()
      xhrRef.current = xhr
      setProgress(0)
      setStatus('uploading')
      // Fires many times a second while the body is being sent.
      xhr.upload.onprogress = (e) => {
        if (e.lengthComputable) setProgress(e.loaded / e.total)
      }
      xhr.onload = () => {
        if (xhr.status >= 200 && xhr.status < 300) {
          setProgress(1) // the server has it: now it's really done
          setStatus('done')
        } else {
          setStatus('error')
        }
      }
      xhr.onerror = () => setStatus('error')
      const body = new FormData()
      body.append('file', file)
      xhr.open('POST', url)
      xhr.send(body)
    },
    [url],
  )

  const cancel = useCallback(() => {
    xhrRef.current?.abort()
    setStatus('idle')
    setProgress(0)
  }, [])

  return { progress, status, start, cancel }
}
```

## The upload widget

```tsx title="src/UploadRing.tsx"
import { An1Player } from './an1mbyt3/an1mbyt3-react.js'
import { useUpload } from './useUpload'

const LABELS = { idle: 'Choose a file', uploading: 'Uploading', done: 'Uploaded', error: 'Upload failed' }
const COLORS = { idle: '#7c5cff', uploading: '#7c5cff', done: '#22a861', error: '#e5484d' }

export function UploadRing() {
  const { progress, status, start, cancel } = useUpload('/api/upload')

  // Don't let the ring reach 100 % before the server answers: the bytes
  // can be sent while the server is still processing them.
  const shown = status === 'done' ? 1 : Math.min(progress, 0.99)

  return (
    <div>
      <An1Player
        game="/an1mbyt3/game.teab"
        style={{ width: 240, height: 240 }}
        // progress can change 60 times a second: fine, only changes are sent.
        data={{ progress: shown, label: LABELS[status], color: COLORS[status] }}
        onEvent={(e) => {
          // From the ring's script: ctx.emit('done', {})
          if (e.name === 'done') console.log('ring finished its Done animation')
        }}
      />
      <input type="file" onChange={(e) => e.target.files?.[0] && start(e.target.files[0])} />
      {status === 'uploading' && <button onClick={cancel}>Cancel</button>}
    </div>
  )
}
```

## Try it live

No server here, so this version simulates an upload with a random speed. Start one, cancel it, or make it fail.

```jsx live
function SimulatedUpload() {
  const [progress, setProgress] = React.useState(0)
  const [status, setStatus] = React.useState('idle')
  const [log, setLog] = React.useState([])
  const timer = React.useRef(null)
  const add = (s) => setLog((l) => [s, ...l].slice(0, 5))

  const start = (fail) => {
    clearInterval(timer.current)
    setProgress(0)
    setStatus('uploading')
    let p = 0
    timer.current = setInterval(() => {
      p += 0.01 + Math.random() * 0.04
      if (fail && p > 0.6) {
        clearInterval(timer.current)
        setStatus('error')
        return
      }
      if (p >= 1) {
        clearInterval(timer.current)
        setProgress(1)
        setStatus('done')
        return
      }
      setProgress(Math.min(p, 0.99))
    }, 80)
  }
  React.useEffect(() => () => clearInterval(timer.current), [])

  const labels = { idle: 'Ready', uploading: 'Uploading', done: 'Uploaded', error: 'Upload failed' }
  const colors = { idle: '#7c5cff', uploading: '#7c5cff', done: '#22a861', error: '#e5484d' }

  return (
    <div>
      <ToastyPlayer
        game="/games/progress-ring.teab"
        style={{ width: 240, height: 240 }}
        data={{ progress, label: labels[status], color: colors[status] }}
        onEvent={(e) => add('event: ' + e.name)}
        onStateChange={(e) => add('state: ' + e.state)}
      />
      <button onClick={() => start(false)}>Upload</button>{' '}
      <button onClick={() => start(true)}>Upload (will fail)</button>
      <ul>{log.map((l, i) => <li key={i}>{l}</li>)}</ul>
    </div>
  )
}
```

## How it works

### High-frequency data is fine

`setProgress` runs on every `progress` event, and the component passes the value straight into `data`. React's `An1Player` sends only the keys whose value changed, the Property takes the new number, and the binding updates the trim on the next frame. There's no need to throttle.

### Who decides "done"?

The page does. `progress` stays below `0.99` until the server's response arrives, because "all bytes sent" isn't "saved". Then the page sets `1`, the ring's script sets `complete`, the state machine enters Done, and the script emits `done`. The page sees both:

- **`onStateChange`** with `state: 'Done'` the moment the look changes;
- **`onEvent`** with `name: 'done'`, sent by the scene's script.

Use whichever reads better. A common pattern is to wait for the finished animation before moving on:

```tsx
// With the player handle from onReady (or a ref):
await player.waitForState('Done')
navigate('/files')
```

`waitForState` resolves immediately if the ring is already in `Done`.

### Errors and retries

On an error the page keeps the last progress, switches `label` to "Upload failed" and `color` to red. Starting again sets `progress` back to `0`: the ring's `complete` input goes false and the state machine returns to Loading.

## Check your work

- In the live demo, **Upload** fills the ring smoothly, then the log shows `state: Done` and `event: done`.
- **Upload (will fail)** stops around 60 % with a red "Upload failed".
- Starting a new upload after a finished one goes back to Loading (`state: Loading` in the log).
