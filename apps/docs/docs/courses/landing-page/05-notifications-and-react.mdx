# 5. Notifications and the finished page

**Goal:** a notification bell in the header. It shows a red badge while there are unread notifications, rings when a new one arrives, and opens an inbox panel. Then the finished page, and the same page in React.

The `bell` icon's API:

| Input | Kind | Effect |
|---|---|---|
| `unread` | Bool | Pops the red badge in (true) or out (false). It is on its own layer, so it works during a ring. |
| `ring` | Trigger | Swings the bell with a decaying rotation. Firing it again mid-swing restarts it. |
| `hover` | Bool | Tilts the bell slightly. |

When the bell handles its own click, it also sends the page a `toasty:event` named `open`. Here the page owns the click, so it doesn't need that event.

## How it works

- **`unread` is a fact, `ring` is a moment.** The badge follows a Bool that the page keeps in step with its unread count. The swing is a Trigger the page fires when something arrives, and also on click as feedback.
- **Opening the inbox marks everything read**, so the page sets `unread` to false and the badge pops out. The button's `aria-label` carries the count for screen readers: "Notifications, 2 unread".
- **Escape and a click outside close the panel**, like any menu.
- **Five components, one loop.** The mascot, theme switch, two arrows, status icon and bell share one requestAnimationFrame loop. Each repaints only when something changes, and pauses when scrolled out of view, so an idle page costs almost nothing.

## The React port

The **React** tab above has the same page as components. Each icon is a `<ToastyLite>`; its props are diffed, so changing `inputs` or `ink` updates the running icon without reloading it.

| HTML version | React version |
|---|---|
| `inputs` attribute | `inputs` prop |
| `ink="currentColor"` | `ink` prop with a colour derived from the theme state (the prop is a fixed CSS colour, so pass a new one when the theme changes) |
| `icon.player.fire('ring')` | `ref` to the player, then `bell.current?.fire('ring')` |
| `hoverInput(el, icon)` | A `useHover()` hook that returns `hover` and the event props |

Every component in the React port owns its own state, except the theme and the notifications, which live in `LandingPage` because more than one component needs them.
