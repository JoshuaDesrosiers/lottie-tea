# 6. Ship it in a real page

**Goal:** the heart inside a real `<button>` on a social post. The button owns the state, so it works with the mouse, the keyboard and screen readers. The heart only shows that state, and its line colour follows the button's text colour.

## The files

Copy these next to your site's other static files:

```text
public/
  toasty/
    an1mbyt3-lite.js        the <toasty-lite> element and createLite()
    an1mbyt3-runtime.js     imported by an1mbyt3-lite.js; keep it in the same folder
    lite/
      heart.json            your export from lesson 5
```

[Toasty Lite](../../runtimes/lite.mdx) explains where the two runtime files come from. The examples below load the shipped `heart.json`; yours behaves the same.

import { ToastyLite } from './toasty/an1mbyt3-lite-react.js'

type LikeButtonProps = {
  postId: string
  initialLiked: boolean
  initialCount: number
  /** Line colour while not liked: any CSS colour. */
  ink?: string
}

export function LikeButton({ postId, initialLiked, initialCount, ink = '#6b6b76' }: LikeButtonProps) {
  const [liked, setLiked] = useState(initialLiked)
  const [count, setCount] = useState(initialCount)
  const [hover, setHover] = useState(false)

  async function toggle() {
    const next = !liked
    setLiked(next)
    setCount((c) => c + (next ? 1 : -1))
    try {
      const res = await fetch('/api/posts/' + postId + '/like', { method: next ? 'PUT' : 'DELETE' })
      if (!res.ok) throw new Error('Like failed: ' + res.status)
    } catch {
      setLiked(!next)
      setCount((c) => c + (next ? -1 : 1))
    }
  }

  return (
    <button
      type="button"
      className="like"
      aria-pressed={liked}
      aria-label="Like this post"
      onClick={toggle}
      onPointerEnter={() => setHover(true)}
      onPointerLeave={() => setHover(false)}
    >
      <ToastyLite
        src="/toasty/lite/heart.json"
        inputs={{ liked, hover }}
        ink={liked ? '#e11d48' : ink}
        style={{ width: 32, height: 32, pointerEvents: 'none' }}
      />
      <span className="count">{count.toLocaleString()}</span>
    </button>
  )
}`}

## How it works

- **The button owns the value; the heart displays it.** In lesson 4 you gave the heart its own click behaviour. Here, `pointer-events: none` on `<toasty-lite>` switches that off, so the button receives every click, including keyboard activation with Space and Enter, which never reaches a canvas. The page sets `liked` and the state machine plays the right animation. The page code never needs to know the state names.
- **`aria-pressed` is the accessible state.** A screen reader announces "Like this post, toggle button, pressed". The canvas inside is decorative, so the button's label and `aria-pressed` carry the meaning.
- **`inputs` is live.** Changing the attribute after the heart has loaded sends the new values straight to the running state machine. Changing it before the heart has loaded is also fine, because the element reads the attribute when it starts. That is how a post that was already liked opens in the liked state: render it with `inputs='{"liked":true}'`.
- **Hover comes from the button, too.** `pointerenter` and `pointerleave` on the whole button set the `hover` input, so the heart grows when the pointer is anywhere over the pill, not only over the heart.
- **`ink="currentColor"` follows the button's text colour.** The outline is muted at rest, darkens with the button's `:hover` colour in CSS, and turns red with `aria-pressed="true"`. The element re-reads `currentColor` when `<html>` changes its class, `data-theme` or `style`, and when the system colour scheme changes.
- **Optimistic updates.** The count changes immediately and rolls back if the save fails. The animation needs no special handling; setting `liked` back to false crossfades the heart to rest.
- **React.** `<ToastyLite>` diffs its props, so changing `inputs`, `data` or `ink` updates the running heart without a reload. Its `ink` prop takes any CSS colour string and sets the `ink` Property. See [React](../../runtimes/react.mdx).

### When the heart should toggle itself

If the heart sits on its own, without a surrounding button, you can keep its built-in click and listen for what happened. The shipped file names its base states `Unliked` and `Liked`:

```html
<toasty-lite id="like" src="/toasty/lite/heart.json" ink="currentColor" style="width:40px;height:40px"></toasty-lite>
<script type="module">
  const heart = document.getElementById('like')
  heart.addEventListener('toasty:state', (e) => {
    // The Hover layer reports too; the base layer is null.
    if (e.detail.layer !== null) return
    const liked = e.detail.state === 'Liked'
    console.log(liked ? 'liked' : 'unliked')
  })
</script>
```

If you exported your own file in lesson 5, use your state names here (for example `State 2`), or use the button pattern above, which does not depend on them.

## Check your work

- Clicking the pill anywhere toggles the heart and the count; the burst plays only when liking.
- Tab to the button and press Space: the same thing happens, and a focus ring is visible.
- Switch the docs between light and dark mode: the resting outline keeps matching the button's text.
- Reload the frame and click quickly several times: the count and the heart always agree.
