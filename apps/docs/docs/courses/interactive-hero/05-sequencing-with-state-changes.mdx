# 5. Sequencing the page with state changes

**Goal:** page UI that moves in step with the animation: things appear, unlock or change *because* the scene reached a state.

**What you'll learn**

- `onStateChange` as a cue track for the page.
- Keeping cue state in React, and why not to derive it from your own inputs.
- `waitForState` for linear intro sequences.
- Ignoring states from other layers.

## Cues from states

Every time a state machine layer enters a state, the player reports `{ layer, state, previous }`. `layer` is `null` for the base layer, or a layer's name. In React that's `onStateChange`; in plain JavaScript it's `player.on('state', …)`.

Why not just react to your own data? Because the scene owns the timing. You set `isNight: true`, but the scene decides *when* it's actually night (after its transition). Cueing page UI from the state keeps the page and the animation in sync even if an artist later makes the sunset slower.

## Example: reveal on nightfall, unlock on happiness

```tsx title="src/StagedHero.tsx"
import { useState } from 'react'
import { An1Player } from './an1mbyt3/an1mbyt3-react.js'

export function StagedHero() {
  const [isNight, setIsNight] = useState(false)
  const [nightReached, setNightReached] = useState(false)

  return (
    <header>
      <An1Player
        game="/an1mbyt3/game.teab"
        style={{ width: 320, height: 200 }}
        data={{ isNight }}
        inputs={{ isNight }}
        onEvent={(e) => e.name === 'toggle' && setIsNight((e.payload as { isNight: boolean }).isNight)}
        onStateChange={(e) => {
          if (e.layer !== null) return // only the base layer's Day / Night
          if (e.state === 'Night') setNightReached(true)
        }}
      />
      {/* Hidden until night has fallen at least once: a little secret for the curious. */}
      <p className={nightReached ? 'reveal shown' : 'reveal'}>Night owl? We ship dark mode on every plan.</p>
    </header>
  )
}
```

```css
.reveal { opacity: 0; transform: translateY(8px); transition: opacity 0.6s, transform 0.6s; }
.reveal.shown { opacity: 1; transform: none; }
```

## Try it live

Two cues at once: night reveals a line, and the sign-up button unlocks only while the blob is in its `Happy` state. Switch between the two cards to try each scene.

```jsx live
function Cues() {
  const [which, setWhich] = React.useState('toggle')
  const [isNight, setIsNight] = React.useState(false)
  const [nightReached, setNightReached] = React.useState(false)
  const [mood, setMood] = React.useState(0)
  const [blobState, setBlobState] = React.useState('')
  return (
    <div>
      <p>
        <button onClick={() => setWhich('toggle')} disabled={which === 'toggle'}>Day / night</button>{' '}
        <button onClick={() => setWhich('mood')} disabled={which === 'mood'}>Mood blob</button>
      </p>
      {which === 'toggle' ? (
        <div>
          <ToastyPlayer
            game="/games/day-night.teab"
            style={{ width: 320, height: 200 }}
            data={{ isNight }}
            inputs={{ isNight }}
            onEvent={(e) => e.name === 'toggle' && setIsNight(e.payload.isNight)}
            onStateChange={(e) => e.layer === null && e.state === 'Night' && setNightReached(true)}
          />
          <p style={{ opacity: nightReached ? 1 : 0, transition: 'opacity 0.6s' }}>Night owl? We ship dark mode on every plan.</p>
        </div>
      ) : (
        <div>
          <ToastyPlayer
            game="/games/mood-blob.teab"
            style={{ width: 240, height: 240 }}
            data={{ mood }}
            onStateChange={(e) => e.layer === null && setBlobState(e.state)}
          />
          <input type="range" min={-1} max={1} step={0.05} value={mood} onChange={(e) => setMood(Number(e.target.value))} />
          <p>
            <button disabled={blobState !== 'Happy'}>{blobState === 'Happy' ? 'Sign up' : 'Make the blob happy first'}</button>
          </p>
        </div>
      )}
    </div>
  )
}
```

## A scripted intro with `waitForState`

For a linear sequence ("when the intro finishes, show the headline, then the button"), an `async` function reads better than state flags. `waitForState(state, layer?)` returns a promise that resolves when the base layer (or the named layer) is in that state, immediately if it already is.

```tsx title="src/IntroHero.tsx"
import { useState } from 'react'
import { An1Player, type An1PlayerHandle } from './an1mbyt3/an1mbyt3-react.js'

export function IntroHero() {
  const [step, setStep] = useState(0) // 0 nothing, 1 headline, 2 headline + button

  async function play(player: An1PlayerHandle) {
    // Start in day, then fall to night: the Property and the input together,
    // exactly like data={{ isNight }} inputs={{ isNight }} in lesson 2.
    player.set('isNight', true)
    player.setInput('isNight', true)
    await player.waitForState('Night')
    setStep(1)
    // A beat later, the call to action.
    await new Promise((r) => setTimeout(r, 600))
    setStep(2)
  }

  return (
    <header>
      <An1Player game="/an1mbyt3/game.teab" style={{ width: 320, height: 200 }} onReady={play} />
      {step >= 1 && <h1 className="reveal shown">Build things that feel alive</h1>}
      {step >= 2 && <a className="reveal shown" href="/signup">Start free</a>}
    </header>
  )
}
```

`onReady` runs once, when the scene has loaded and is running, with the player handle: the natural place to start a sequence.

:::caution Don't wait forever
`waitForState` waits as long as it takes. If the state might never come (the visitor navigates away, or the scene changed), race it against a timeout: `await Promise.race([player.waitForState('Night'), new Promise((r) => setTimeout(r, 3000))])`.
:::
