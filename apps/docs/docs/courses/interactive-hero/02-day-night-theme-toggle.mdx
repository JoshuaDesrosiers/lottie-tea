# 2. A theme-driven day/night toggle

**Goal:** clicking the scene switches the whole site between light and dark, the site's own toggle switches the scene, and both start from the visitor's saved choice or OS preference.

**What you'll learn**

- One source of truth (React state) driving both the DOM theme and the scene.
- Sending a value as both `data` and an `inputs` entry.
- Handling the `toggle` event without fighting the page's state.
- `prefers-color-scheme` and `localStorage` for the starting theme.

## Step 1: the theme hook

```tsx title="src/useTheme.ts"
import { useCallback, useEffect, useState } from 'react'

export type Theme = 'light' | 'dark'
const KEY = 'theme'

/** The starting theme: a saved choice, else the OS preference. */
function initialTheme(): Theme {
  try {
    const saved = localStorage.getItem(KEY)
    if (saved === 'light' || saved === 'dark') return saved
  } catch {
    // storage blocked (private mode): fall through
  }
  return window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
}

export function useTheme() {
  const [theme, setThemeState] = useState<Theme>(initialTheme)

  // Reflect it on <html data-theme="..."> for your CSS.
  useEffect(() => {
    document.documentElement.dataset.theme = theme
  }, [theme])

  // A choice the visitor makes is saved.
  const setTheme = useCallback((next: Theme) => {
    setThemeState(next)
    try {
      localStorage.setItem(KEY, next)
    } catch {
      // ignore
    }
  }, [])

  // Follow OS changes while the visitor hasn't chosen.
  useEffect(() => {
    const mq = window.matchMedia('(prefers-color-scheme: dark)')
    const onChange = () => {
      let saved: string | null = null
      try {
        saved = localStorage.getItem(KEY)
      } catch {
        // ignore
      }
      if (!saved) setThemeState(mq.matches ? 'dark' : 'light')
    }
    mq.addEventListener('change', onChange)
    return () => mq.removeEventListener('change', onChange)
  }, [])

  return { theme, setTheme }
}
```

## Step 2: the hero

```tsx title="src/Hero.tsx"
import { An1Player } from './an1mbyt3/an1mbyt3-react.js'
import { useTheme } from './useTheme'

export function Hero() {
  const { theme, setTheme } = useTheme()
  const isNight = theme === 'dark'

  return (
    <header className="hero">
      <h1>Build things that feel alive</h1>
      <An1Player
        game="/an1mbyt3/game.teab"
        style={{ width: 320, height: 200 }}
        // The scene's Property (for anything bound to it) and its state
        // machine input (for the Day/Night transition) both follow the theme.
        data={{ isNight }}
        inputs={{ isNight }}
        // A click on the scene asks for the other theme.
        onEvent={(e) => {
          if (e.name === 'toggle') setTheme((e.payload as { isNight: boolean }).isNight ? 'dark' : 'light')
        }}
      />
      {/* A normal, accessible toggle too: both control the same state. */}
      <button type="button" aria-pressed={isNight} onClick={() => setTheme(isNight ? 'light' : 'dark')}>
        {isNight ? 'Dark' : 'Light'} mode
      </button>
    </header>
  )
}
```

```css title="src/theme.css"
:root { --bg: #f7f7fa; --fg: #16161d; }
:root[data-theme='dark'] { --bg: #101018; --fg: #ececf4; }
body { background: var(--bg); color: var(--fg); transition: background 0.4s, color 0.4s; }
```

## How it works

### One source of truth

The theme lives in React state. Everything else follows it: the `data-theme` attribute (and so your CSS), the scene's `isNight` Property, and its `isNight` input. Neither the scene nor the button changes the theme directly: both *ask* by calling `setTheme`. That way they can't disagree.

### `data` and `inputs`

`data` writes scene **Properties** (for bindings and scripts); `inputs` writes **state machine inputs** (for transitions). The day/night scene has both named `isNight`, so the hero sends the value to both. Sending a value something already has changes nothing, so this is safe on every render. See [Data binding](../../embedding/data-binding.mdx).

### The `toggle` event

When the visitor clicks the scene, it emits `toggle` with the theme it wants (`{ isNight }`). The page sets that theme, and the new value flows back through `data` / `inputs`. Because the event carries the *desired value*, not "a click happened", the page never has to guess what the scene meant.

### First paint

`initialTheme` runs before the first render, so the scene starts in the right state with no flash from Day to Night. (To avoid a flash of the wrong *page* colours on a server-rendered site, also set `data-theme` in a tiny inline script in `<head>`; that's a general dark-mode concern, not a Toasty one.)

## Check your work

- Clicking the scene switches the site's colours, and the scene shows Night; clicking again returns to Day.
- The button and the scene always agree.
- In your app, reload after choosing dark: it starts dark. Clear the saved choice and switch your OS theme: the page follows.
