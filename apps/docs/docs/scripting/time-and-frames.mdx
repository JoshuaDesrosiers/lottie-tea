# Time and frames

Your script runs once per displayed frame. Frame rates vary (60, 120, 144 Hz, or slower on a busy laptop), so anything that moves or counts down should be scaled by the time that actually passed.

| Member | Type | Description |
|---|---|---|
| `ctx.deltaSeconds` | number | Seconds since the previous frame |
| `ctx.time` | number | Seconds since **this layer's** current state became active |
| `ctx.screen` | object | The size and shape of the screen this frame was laid out for |

## ctx.deltaSeconds

```ts
ctx.deltaSeconds: number
```

Seconds since the last frame, about `0.0167` at 60 fps. Multiply speeds by it.

```js
const SPEED = 240                                    // units per second
getCompByID('car').x += SPEED * ctx.deltaSeconds
```

**Gotchas**
- It is `0` on the very first frame.
- After a hitch (a tab switch, a breakpoint) it can be large. The exported player caps it at `0.1`; the editor does not. Clamp it yourself for physics-like code, as every demo does:

```js
const dt = Math.min(ctx.deltaSeconds, 1 / 20)
```

The player moves by `speed * dt`; `coin0` moves a fixed amount per frame, so its speed depends on your display's refresh rate:

<ScriptLab
  title="Per second vs per frame"
  code={`const dt = Math.min(ctx.deltaSeconds, 1 / 20)
const player = getCompByID('player')
const coin = getCompByID('coin0')
player.x += 120 * dt             // 120 units per second on any display
coin.x += 2                      // 2 units per frame: twice as fast at 120 Hz
if (player.x > 240) player.x = -240
if (coin.x > 240) coin.x = -240
const fps = Math.round(1 / Math.max(ctx.deltaSeconds, 0.001))
ctx.props.message = 'dt ' + (ctx.deltaSeconds * 1000).toFixed(1) + ' ms (about ' + fps + ' fps)'`}
/>

## ctx.time

```ts
ctx.time: number
```

Seconds since the current state became active on this program's layer. Restarts at `0` every time that layer changes state. Great for "since this state began" logic and for smooth looping motion.

```js
const ufo = getCompByID('ufo')
ufo.y = 120 + Math.sin(ctx.time * 2) * 10      // bob forever
if (ctx.time > 3) ctx.fireTrigger('timeUp')    // leave this state after 3 s
```

If you need a clock that runs across state changes, keep your own:

```js
const g = ctx.globals.clock || (ctx.globals.clock = { t: 0 })
g.t += ctx.deltaSeconds
```

or use `performance.now() / 1000` (wall-clock seconds, keeps running while paused).

Press **Excite** to change state: `ctx.time` starts again from 0 while the clock on `ctx.globals` keeps running. The script itself returns to `Calm` after 3 seconds.

<ScriptLab
  title="ctx.time restarts on every state change"
  code={`const g = ctx.globals.clock || (ctx.globals.clock = { t: 0 })
g.t += ctx.deltaSeconds                               // your own clock
const player = getCompByID('player')
player.y = -40 + Math.sin(ctx.time * 3) * 40          // bob, restarting with the state
if (ctx.state === 'Excited' && ctx.time > 3) ctx.setInput('excited', false)   // calm down after 3 s
ctx.props.message = ctx.state + ': ctx.time ' + ctx.time.toFixed(1) + ' s   own clock ' + g.t.toFixed(1) + ' s'`}
  controls={[{ label: 'Excite', input: ['excited', true] }, { label: 'Calm', input: ['excited', false] }]}
/>

## Timers

Timers are just numbers in `ctx.globals` that you count down or compare against.

**Count down:**

```js
const g = ctx.globals.spawner || (ctx.globals.spawner = { next: 1 })
g.next -= ctx.deltaSeconds
if (g.next <= 0) {
  g.next = 0.8                        // every 0.8 s
  ctx.spawn('Enemy', 300, Math.random() * 200 - 100)
}
```

The lab scene has no prefab to spawn, so this timer reveals one coin every 0.8 seconds instead:

<ScriptLab
  title="A countdown timer"
  code={`const g = ctx.globals.timer || (ctx.globals.timer = { next: 0.8, shown: 0 })
g.next -= ctx.deltaSeconds
if (g.next <= 0) {
  g.next = 0.8                          // every 0.8 s
  g.shown = (g.shown + 1) % 6           // 0..5 coins, then start over
  print('showing ' + g.shown + ' coins')
}
getCompByClass('coin').forEach((coin, i) => { coin.visible = i < g.shown })
ctx.props.message = 'next coin in ' + g.next.toFixed(2) + ' s'`}
/>

**Schedule for later (compare with `ctx.time`):**

```js
// play a second note 0.08 s after the first
if (coinClicked) { ctx.playTone({ freq: 988, duration: 0.08 }); g.coinAt = ctx.time + 0.08 }
if (g.coinAt && ctx.time >= g.coinAt) { ctx.playTone({ freq: 1319, duration: 0.25 }); g.coinAt = 0 }
```

<ScriptLab
  title="Schedule a second note"
  code={`const g = ctx.globals.notes || (ctx.globals.notes = { coinAt: 0 })
if (ctx.tap) {
  ctx.playTone({ freq: 988, duration: 0.08 })
  g.coinAt = ctx.time + 0.08
}
if (g.coinAt && ctx.time >= g.coinAt) {
  ctx.playTone({ freq: 1319, duration: 0.25 })
  g.coinAt = 0
}
ctx.props.message = 'Click the stage for a coin sound'`}
  hint="Turn your sound on, then click the stage."
/>

`setTimeout` also works (scripts are normal JS), but the callback runs outside the frame, with no fresh `ctx` and no pause awareness. Prefer frame-based timers.

## Smooth motion

**Ease towards a target**, frame-rate independent:

```js
const k = 1 - Math.exp(-10 * ctx.deltaSeconds)     // 10 = how snappy
cam.x += (player.x - cam.x) * k
```

**Linear interpolation** with the built-in `lerp(a, b, t)` (t clamped to 0..1):

```js
const t = Math.min(1, ctx.time / 0.5)              // 0 -> 1 over half a second
panel.y = lerp(-400, 0, t * t * (3 - 2 * t))       // smoothstep ease
```

The player eases towards the mouse; `coin2` slides up with a smoothstep each time the state starts:

<ScriptLab
  title="Easing and lerp"
  code={`const player = getCompByID('player')
const k = 1 - Math.exp(-6 * ctx.deltaSeconds)      // 6 = how snappy
player.x += (ctx.mouseX - player.x) * k
player.y += (ctx.mouseY - player.y) * k

const t = Math.min(1, ctx.time / 0.5)              // 0 -> 1 over half a second
getCompByID('coin2').y = lerp(-80, 40, t * t * (3 - 2 * t))`}
  controls={[{ label: 'Excite', input: ['excited', true] }, { label: 'Calm', input: ['excited', false] }]}
  hint="Move the mouse over the stage. Excite or Calm restarts ctx.time, which replays the coin's slide."
/>

## Running something once when a state starts

`ctx.time` is `0` on a state's first frame, but a robust check stores the state you last saw (per layer):

```js
const g = ctx.globals.flow || (ctx.globals.flow = { cur: {} })
function entered() {
  const key = ctx.layer || 'base'
  if (g.cur[key] === ctx.state) return false
  g.cur[key] = ctx.state
  return true
}
if (entered()) { ctx.playSound('whoosh'); ctx.props.timer = 30 }
```

The lab's two states share this program; the block inside `entered()` runs once per visit:

## ctx.screen

```ts
ctx.screen: {
  width: number         // visible world area, world units
  height: number
  screenWidth: number   // CSS pixels
  screenHeight: number
  compact: boolean      // narrower than the scene's breakpoint (phones)
  portrait: boolean     // taller than wide
}
```

What the current frame was laid out for. Use it to adapt layout from code.

```js
const hud = getCompByID('hud')
hud.x = -ctx.screen.width / 2 + 20                  // pin to the left edge
hud.scaleX = hud.scaleY = ctx.screen.compact ? 0.8 : 1
```

<ScriptLab
  title="Read ctx.screen"
  code={`const s = ctx.screen
const player = getCompByID('player')
player.x = -s.width / 2 + 30          // pinned near the top-left corner
player.y = s.height / 2 - 30
ctx.props.message = Math.round(s.width) + ' x ' + Math.round(s.height) + ' units, '
  + Math.round(s.screenWidth) + ' x ' + Math.round(s.screenHeight) + ' px'
  + (s.compact ? ', compact' : '') + (s.portrait ? ', portrait' : '')`}
  hint="Resize the browser window to see the values change."
/>
