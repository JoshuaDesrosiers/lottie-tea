# The `<an1-player>` element

If you'd rather write HTML than JavaScript (a CMS page, a static site, a framework without a wrapper), register the custom element once and use the tag anywhere:

```html
<script type="module">
  import { defineAn1PlayerElement } from '/an1mbyt3/an1mbyt3-embed.js'
  defineAn1PlayerElement()
</script>

<an1-player
  game="/an1mbyt3/game.teab"
  data='{"speed": 1}'
  style="height: 360px">
</an1-player>
```

With Toast Catch as `game.teab`, that tag shows this:

<ToastyDemo game="/games/toast-catch.teab" height={360} data={{ speed: 1 }} caption="toast-catch.teab with data speed 1. Click to play." />

:::tip Animated icons and buttons
This element runs the full engine; a page can hold several, each with its own game. For UI animation, the [Toasty Lite](../runtimes/html.mdx) element `<toasty-lite>` is about 25 KB and you can use as many as you like.
:::

## Registering

`defineAn1PlayerElement(tag?)` registers the element. Call it once, before or after the tags appear in the page; tags already in the page start as soon as it is registered.

- The default tag name is `an1-player`. Pass another name to use your own, for example `defineAn1PlayerElement('arcade-game')` (custom element names must contain a dash).
- Calling it again with a name that's already registered does nothing, so it's safe to call from several scripts.

## Attributes

| Attribute | Value | Changing it |
|---|---|---|
| `game` | URL of the `.teab`. **Required**; nothing loads without it. | reloads the player |
| `wasm` | URL of the engine. Default: `an1mbyt3_wasm_bg.wasm` next to `game`. | reloads |
| `scene` | Scene name to show. Default: the first scene. | switches scene (live) |
| `data` | A JSON object of data, for example `'{"speed": 1.5}'`. | sends every key in it (live) |
| `paused` | Boolean attribute: present means paused. | pauses / plays (live) |
| `fit` | `contain` (default) or `cover`. | reloads |
| `keyboard` | `focus` (default), `window` or `none`. | reloads |

What each value means is the same as the [`createPlayer` options](./api-reference.mdx#createplayer-options). Two options aren't available as attributes: `background` (style the element instead, for example `style="background:#000"`) and `stats`.

:::caution `data` must be valid JSON
Use double quotes inside and single quotes around the attribute: `data='{"speed": 1.5}'`. If it doesn't parse, the console shows ``<an1-player>: `data` must be JSON`` and the data is ignored.
:::

### Sizing

The element makes itself `display: block` unless you set a `display` yourself, and the game fills it (letterboxed). **Give it a height**, inline or from your stylesheet:

```css
an1-player { display: block; height: 360px; border-radius: 12px; overflow: hidden; }
```

## Changing attributes from code

Set attributes and the running game follows:

```js
const el = document.querySelector('an1-player')

el.setAttribute('data', JSON.stringify({ speed: 1.5 }))  // live
el.setAttribute('scene', 'Level 2')                      // live
el.toggleAttribute('paused', true)                       // live
el.setAttribute('game', '/an1mbyt3/hop.teab')            // reloads
```

When `data` changes, every key in the new JSON is sent (keys that kept their value change nothing in the game, so that's cheap). Removing the `data` or `scene` attribute doesn't undo anything; set new values instead.

:::note Wait for `an1:ready` before changing `scene`, `data` or `paused`
Attribute changes made while the game is still loading are not applied to it (the load reads the attributes when it starts). Set your starting values in the HTML, and make later changes after `an1:ready`.
:::

## The full API: `element.player`

After the game is ready, `element.player` is the same player object `createPlayer` returns, with every method: `set`, `setData`, `get`, `setInput`, `fire`, `loadScene`, `call`, `on`, `off`, `waitForState`, `pause`, `play`. Before that, and after the element is removed, it is `null`.

```js
const el = document.querySelector('an1-player')
el.addEventListener('an1:ready', () => {
  console.log('lives at start:', el.player.get('lives'))
  el.player.set('speed', 1.2)
})
```

## Events

Every event from the player reaches the element as a DOM event, and they all **bubble**, so you can listen on the element itself or on any ancestor. `an1:ready` fires once, after `el.player` is set.

| Event | `detail` | When |
|---|---|---|
| `an1:ready` | `{ scenes, scene }` | the game is loaded and running; `el.player` is set |
| `an1:event` | `{ name, payload }` | the game called `ctx.emit(name, payload)` (or an unhandled On Click "Call script function") |
| `an1:prop` | `{ name, value }` | the game changed one of its scene Properties |
| `an1:state` | `{ layer, state, previous }` | a state machine layer entered a state |
| `an1:scene` | `{ scene, previous }` | the scene switched |
| `an1:error` | `{ error }` | the game failed to load, or a frame threw while running |

The player dispatches `an1:event`, `an1:prop`, `an1:state`, `an1:scene` and running errors on the element's inner box (the `div` the element creates to hold the canvas), and they bubble up through the element. The element itself dispatches `an1:ready` once `el.player` is set, and `an1:error` when loading fails.

An `an1:scene` listener on the element also hears the start scene, which `player.on('scene')` subscribed after `an1:ready` does not.

A complete page with a live score and a best-score line, no framework:

```html
<section class="game-card">
  <an1-player id="toast" game="/an1mbyt3/game.teab" data='{"speed": 1}' style="height: 360px"></an1-player>
  <p>Score <b id="score">0</b> · Lives <b id="lives">3</b> · Best <b id="best">0</b></p>
</section>

<script type="module">
  import { defineAn1PlayerElement } from '/an1mbyt3/an1mbyt3-embed.js'
  defineAn1PlayerElement()

  const card = document.querySelector('.game-card')
  let best = 0

  card.addEventListener('an1:prop', (e) => {
    const { name, value } = e.detail
    if (name === 'score' || name === 'lives') document.getElementById(name).textContent = value
  })
  card.addEventListener('an1:event', (e) => {
    if (e.detail.name !== 'gameover') return
    best = Math.max(best, e.detail.payload.score)
    document.getElementById('best').textContent = best
  })
  card.addEventListener('an1:error', (e) => console.error('game failed', e.detail.error))
</script>
```

You can also subscribe through `el.player.on(...)` after `an1:ready`, which gives you the payload directly instead of in `detail`.

## Lifecycle

- **Added to the page:** loads the game.
- **Removed from the page:** destroys the player and frees the engine. Moving the element (removing and re-inserting it) loads it again.
- **Several players per page:** each `<an1-player>` runs its own game. The engine downloads once and is shared. Players out of view pause until scrolled back (add `run-offscreen` to keep one running). With `keyboard="window"`, keys go to the player you last clicked.

## In frameworks

The element works anywhere HTML does.

**Svelte** supports custom elements natively:

```svelte
<script>
  import { defineAn1PlayerElement } from './an1mbyt3/an1mbyt3-embed.js'
  defineAn1PlayerElement()
  let speed = $state(1)
</script>

<an1-player game="/an1mbyt3/game.teab" data={JSON.stringify({ speed })} style="height: 360px"></an1-player>
<label>Speed <input type="range" min="0.5" max="2" step="0.1" bind:value={speed}></label>
```

**Vue** needs to be told that `an1-player` isn't a Vue component, in `vite.config`:

```js
vue({ template: { compilerOptions: { isCustomElement: (tag) => tag === 'an1-player' } } })
```

```vue
<an1-player game="/an1mbyt3/game.teab" :data="JSON.stringify({ speed })" style="height: 360px" />
```

**WordPress, Webflow, Squarespace and other CMSs:** upload the three `.js` files, `game.teab` and the `.wasm` to one folder on your host (or media library, if it allows `.wasm` and `.teab` files), then add a custom HTML block with the `<script type="module">` and the tag, using the uploaded URLs.

**React:** prefer [`<An1Player>`](./react.mdx). It diffs props and gives you typed handlers.
