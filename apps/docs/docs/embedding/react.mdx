# React

The export ships a React component, `<An1Player>`, in `an1mbyt3-react.js`. Its props steer the running game **live**: when a prop changes, only what changed is sent to the game. Nothing remounts, nothing reloads, nothing flickers. Pass fetched data straight in, and the labels, bars and colours bound to it update on the next frame.

Every example on this page is live and editable, using the two example games, [Toast Catch](../games/toast-catch.mdx) and [Hop](../games/hop.mdx). Click a game to start it. (Only one game runs at a time on a page, so starting one stops the previous one.)

This page covers the full engine. For animated icons and buttons in React, use `<ToastyLite>` (see [Toasty Lite for React](../runtimes/react.mdx)).

:::info In these docs
The live examples use `ToastyPlayer`, the docs site's wrapper around the real `An1Player`. It has exactly the same props and the same `ref`. In your app you import `An1Player` instead, as in the copyable `tsx` blocks.
:::

## Setup

1. [Export the game](./export-for-web.mdx) and copy `src/an1mbyt3/` into your source folder and `public/an1mbyt3/` into your public folder.
2. Import the component:

```tsx
import { An1Player } from './an1mbyt3/an1mbyt3-react.js'

export function Hero() {
  return <An1Player game="/an1mbyt3/game.teab" style={{ width: '100%', height: 480 }} />
}
```

That's the whole thing. The component renders a `div` (with `position: relative; overflow: hidden` plus your `style` and `className`), creates the player inside it, and destroys the player when it unmounts.

:::caution The box needs a height
The game fits inside the component's box. Without a height (from `style`, `className` or a parent that stretches it) the box is 0 px tall and you see nothing.
:::

`an1mbyt3-react.js` imports `react` and `react/jsx-runtime` from your app, so it uses your copy of React. React 19 is recommended because the `ref` prop relies on React 19's ref-as-a-prop; on React 18 everything else works, and you get the player from `onReady` instead (see [React 18](#react-18)).

## Props at a glance

| Prop | Type | Live? | What it does |
|---|---|---|---|
| `game` | `string`, `URL`, `ArrayBuffer`, `Uint8Array` | reloads | The `.teab` file. Required. |
| `wasm` | same | reloads | The engine. Default: `an1mbyt3_wasm_bg.wasm` next to `game`. |
| `scene` | `string` | live | Which scene plays. Changing it switches scene. |
| `data` | object (`Record<string, unknown>`) | live | Values for `ctx.data` and same-named scene Properties. |
| `inputs` | object of booleans, numbers or strings | live | State machine inputs by name. |
| `paused` | `boolean` | live | Freeze and unfreeze. |
| `fit` | `'contain'` or `'cover'` | reloads | Letterbox (default) or fill and crop. |
| `keyboard` | `'focus'`, `'window'` or `'none'` | reloads | Where key presses come from. Default `'focus'`. |
| `background` | `string` | reloads | Letterbox colour (any CSS colour). |
| `className`, `style` | | live | For the box. |
| `ref` | `Ref<An1PlayerHandle>` | | The full player API once ready. |
| `onReady` | `(player) => void` | | Called once the first scene is running. |
| `onEvent` | `({ name, payload }) => void` | | The game called `ctx.emit`. |
| `onStateChange` | `({ layer, state, previous }) => void` | | A state machine layer entered a state. |
| `onPropChange` | `({ name, value }) => void` | | The game changed a scene Property. |
| `onSceneChange` | `({ scene, previous }) => void` | | The scene switched. |
| `onError` | `(error) => void` | | Loading failed, or a frame threw. |

"Reloads" means changing that prop destroys the player and starts a fresh one. "Live" means the change is sent to the running game. The [API reference](./api-reference.mdx#react-an1player) has every detail.

## Sending data: `data`

`data` is an object of values. Each key reaches `ctx.data` in the game's scripts, and the scene Property with the same name if the scene has one. Toast Catch reads `ctx.data.speed` every frame, so dragging the slider changes the game mid-round:

```jsx live
function SpeedDemo() {
  const [speed, setSpeed] = React.useState(1)
  return (
    <div>
      <ToastyPlayer
        game="/games/toast-catch.teab"
        data={{ speed }}
        style={{ height: 300 }}
      />
      <label style={{ display: 'flex', gap: 12, alignItems: 'center', marginTop: 8 }}>
        Speed
        <input type="range" min="0.5" max="2.5" step="0.1" value={speed}
          onChange={(e) => setSpeed(Number(e.target.value))} />
        <span>{speed.toFixed(1)}×</span>
      </label>
    </div>
  )
}
```

How the updates work:

- The component keeps the last `data` it sent and compares key by key with `Object.is`. **Only keys whose value changed are sent.** Re-rendering with the same values sends nothing, so it is fine to build the object inline on every render.
- The diff is **shallow**. If a value is an object or array and you mutate it in place, the change isn't seen. Pass a new object or array for that key.
- When a key matches a scene Property, the value is converted to the Property's type: a number for Number, `true`, `1`, `'true'`, `'1'` or `'on'` for Bool, a string for Text, and `'#rrggbb'` or `[r, g, b, a]` (0 to 1) for Color. `ctx.data` keeps the value exactly as you sent it.
- Data are kept across scene switches: when the game changes scene, your values are applied to the new scene's Properties too.

[Sending data in](./data-binding.mdx) covers this in depth, including what the game side looks like.

## State machine inputs: `inputs`

`inputs` sets the scene's state machine inputs by name. A Bool, Number or Enum input takes the value you pass:

```tsx
const [paused, setPaused] = useState(false)

<An1Player
  game="/an1mbyt3/game.teab"
  inputs={{ paused, difficulty: 'hard' }}   // a Bool and an Enum input
  style={{ height: 400 }}
/>
```

Toast Catch and Hop keep their logic in a script, so their state machines have no inputs. Inputs matter most for state-machine-driven scenes, which on a website are usually UI animation; for those, [Toasty Lite](../runtimes/lite.mdx) has the same `inputs` prop and runs any number per page.

Like `data`, `inputs` is diffed shallowly; only changed keys are sent. An input name the scene doesn't have logs a warning in the browser console (`the scene's state machine has no input "…"`) and does nothing.

:::caution Triggers in `inputs`
A Trigger input fires when its value **changes to** something truthy. Passing `{ restart: true }` on every render fires it once, not every render. To fire the same trigger again and again, use the player's `fire` method through a `ref` (next section), or flip the value back to `false` between fires.
:::

## Imperative control: `ref`

Some things are actions, not state: "pause now", "read the current score", "call this function". For those, take a `ref`. Once the player is ready, `ref.current` is the full player API (the same object [`createPlayer`](./vanilla-js.mdx) returns): `fire`, `setInput`, `set`, `get`, `loadScene`, `call`, `pause`, `play`, `waitForState`, `on`, and read-only `scene`, `state`, `scenes`, `paused`.

```jsx live
function ScoreProbe() {
  const ref = React.useRef(null)
  const [out, setOut] = React.useState('Start the game, then try the buttons.')
  const show = (label, value) => setOut(label + ' → ' + JSON.stringify(value))
  return (
    <div>
      <ToastyPlayer ref={ref} game="/games/toast-catch.teab" style={{ height: 300 }} />
      <div style={{ display: 'flex', gap: 8, marginTop: 8, flexWrap: 'wrap' }}>
        <button onClick={() => show("get('score')", ref.current?.get('score'))}>get('score')</button>
        <button onClick={() => show("get('lives')", ref.current?.get('lives'))}>get('lives')</button>
        <button onClick={() => show('scene', ref.current?.scene)}>scene</button>
        <button onClick={() => show('state', ref.current?.state)}>state</button>
        <button onClick={() => (ref.current?.paused ? ref.current?.play() : ref.current?.pause())}>pause / play</button>
      </div>
      <pre style={{ marginTop: 8 }}>{out}</pre>
    </div>
  )
}
```

`ref.current` is `null` until the player is ready (and again after it is destroyed), so always use `ref.current?.…`.

### A ref that re-renders: `useAn1Player`

A plain `useRef` doesn't re-render your component when the player becomes ready, so you can't, say, disable a button until then. The React module also exports `useAn1Player()`, which keeps the player in state:

```tsx
import { An1Player, useAn1Player } from './an1mbyt3/an1mbyt3-react.js'

function Controls() {
  const [ref, player] = useAn1Player()
  return (
    <>
      <An1Player ref={ref} game="/an1mbyt3/game.teab" style={{ height: 300 }} />
      <button disabled={!player} onClick={() => player?.pause()}>Pause</button>
    </>
  )
}
```

Under the hood `useAn1Player` is `useState` used as a callback ref, which you can write yourself. Here it is live with Hop:

```jsx live
function HopControls() {
  // The same thing useAn1Player() does: a state setter as the ref.
  const [player, setPlayer] = React.useState(null)
  const [paused, setPaused] = React.useState(false)
  return (
    <div>
      <ToastyPlayer ref={setPlayer} game="/games/hop.teab" style={{ height: 240 }} />
      <div style={{ display: 'flex', gap: 8, alignItems: 'center', marginTop: 8 }}>
        <button disabled={!player} onClick={() => {
          if (player.paused) player.play(); else player.pause()
          setPaused(player.paused)
        }}>
          {paused ? 'Resume' : 'Pause'}
        </button>
        <span>{player ? 'Scene: ' + player.scene : 'Start the game to enable the button.'}</span>
      </div>
    </div>
  )
}
```

## Listening: `onEvent`, `onPropChange`, `onStateChange`, `onSceneChange`

The handler props are how the game talks back. You can write them inline: the component reads the latest handler through a ref, so a new function on every render doesn't resubscribe anything.

```jsx live
function CatchLog() {
  const [log, setLog] = React.useState([])
  const add = (line) => setLog((l) => [line, ...l].slice(0, 8))
  return (
    <div>
      <ToastyPlayer
        game="/games/toast-catch.teab"
        style={{ height: 300 }}
        onReady={(p) => add('ready: scene ' + p.scene + ', state ' + p.state)}
        onEvent={(e) => add('event ' + e.name + ' ' + JSON.stringify(e.payload))}
        onPropChange={(e) => add('prop ' + e.name + ' = ' + JSON.stringify(e.value))}
        onStateChange={(e) => add('state ' + e.previous + ' → ' + e.state)}
      />
      <pre style={{ fontSize: 12, minHeight: 140 }}>{log.join('\n')}</pre>
    </div>
  )
}
```

Catch a slice and you see an `event score` and a `prop score`. Lose a life and you see `prop lives`. A few rules worth knowing:

- **`onEvent`** receives every `ctx.emit(name, payload)`. Toast Catch sends `score` and `gameover`; Hop sends `gameover` with `{ score, best }`.
- **`onPropChange`** reports changes the *game* made to its Properties. Your own `data` writes are not echoed back.
- **`onStateChange`** fires for every state machine layer. `layer` is `null` for the base layer, or the layer's name. Filter with `e.layer === null` if you only care about the base layer. Both example games stay in their one state, `Play`, so they never fire it.
- **The starting state is not reported as a change.** Read it in `onReady` (`player.state`, `player.layerStates`), as above.
- **`onError`** receives loading errors (a 404, a broken file) and errors thrown while running a frame. A frame that throws is skipped and the game keeps running.

[Listening to the game](./listening.mdx) goes deeper, including `waitForState`.

## Switching scenes: `scene`

`scene` names the scene to play; change it and the game switches after the current frame. `onSceneChange` tells you about every switch, including the ones the game makes itself with `ctx.loadScene`.

```tsx
const [scene, setScene] = useState('Menu')

<An1Player
  game="/an1mbyt3/game.teab"
  scene={scene}
  onSceneChange={(e) => setScene(e.scene)}   // keep React in step with the game
  style={{ height: 400 }}
/>
<button onClick={() => setScene('Level 1')}>Play</button>
```

The `onSceneChange` handler writes the scene back into React state. Without that, if the game switched scene on its own, your `scene` prop would still say the old name, and setting it to that same name later would change nothing (the effect only runs when the prop changes).

A name that doesn't exist logs `no scene named "…"` and nothing happens. `player.scenes` lists the valid names. The two example games each have one scene.

## Pausing: `paused`

`paused` freezes the game: no simulation, no rendering, no scripts. A common use is pausing a game when the visitor opens a dialog or switches tabs.

```jsx live
function PauseOnHidden() {
  const [manual, setManual] = React.useState(false)
  const [hidden, setHidden] = React.useState(false)
  React.useEffect(() => {
    const update = () => setHidden(document.visibilityState === 'hidden')
    document.addEventListener('visibilitychange', update)
    return () => document.removeEventListener('visibilitychange', update)
  }, [])
  return (
    <div>
      <ToastyPlayer game="/games/hop.teab" paused={manual || hidden} style={{ height: 240 }} />
      <button onClick={() => setManual((p) => !p)} style={{ marginTop: 8 }}>
        {manual ? 'Resume' : 'Pause'}
      </button>
    </div>
  )
}
```

The same is available imperatively as `ref.current.pause()` / `ref.current.play()`, and `ref.current.paused` tells you which it is. The first frame after resuming has a zero time step, so nothing jumps.

## Swapping games: `game`

Changing `game` (or `wasm`, `fit`, `keyboard`, `background`) destroys the player and loads the new one into the same box. Your `data` and `inputs` are applied to the new game as it starts.

```jsx live
function Arcade() {
  const games = { 'Toast Catch': '/games/toast-catch.teab', Hop: '/games/hop.teab' }
  const [name, setName] = React.useState('Toast Catch')
  const [status, setStatus] = React.useState('')
  return (
    <div>
      <ToastyPlayer
        game={games[name]}
        style={{ height: 300 }}
        onReady={(p) => setStatus('ready: ' + p.scene)}
        onError={(err) => setStatus('failed: ' + err)}
      />
      <div style={{ display: 'flex', gap: 8, marginTop: 8, flexWrap: 'wrap', alignItems: 'center' }}>
        {Object.keys(games).map((g) => (
          <button key={g} onClick={() => { setStatus('loading…'); setName(g) }} disabled={g === name}>{g}</button>
        ))}
        <span>{status}</span>
      </div>
    </div>
  )
}
```

## `fit`, `keyboard` and `background`

- **`fit="contain"`** (default) shows the whole scene frame, letterboxed. **`fit="cover"`** fills the box and crops the overflow, which suits backgrounds and hero banners. Scenes set to Responsive screen mode always fill the box (see [Responsive layout](../components/responsive-layout.mdx)).
- **`keyboard="focus"`** (default) sends key presses to the game only while its canvas has focus; clicking the game focuses it. **`"window"`** sends every key press on the page (like the standalone exported game). **`"none"`** never sends keys. See the caution in [Troubleshooting](./troubleshooting.mdx) before using `"window"` on a page with text fields.
- **`background`** colours the letterbox bars, for example `background="#0b0d12"`.

```tsx
<An1Player game="/an1mbyt3/game.teab" fit="cover" background="#000" keyboard="none" style={{ height: '60vh' }} />
```

## TypeScript

The export ships `an1mbyt3-react.d.ts`, so everything is typed:

```tsx
import { useRef } from 'react'
import { An1Player, type An1PlayerHandle, type PlayerEvents } from './an1mbyt3/an1mbyt3-react.js'

type GameOver = { score: number }

function Game({ onScore }: { onScore: (score: number) => void }) {
  const ref = useRef<An1PlayerHandle | null>(null)
  const onEvent = (e: PlayerEvents['event']) => {
    if (e.name === 'gameover') onScore((e.payload as GameOver).score)
  }
  return <An1Player ref={ref} game="/an1mbyt3/game.teab" onEvent={onEvent} style={{ height: 400 }} />
}
```

The names it exports: `An1Player`, `An1PlayerProps`, `An1PlayerHandle`, `PlayerEvents`, `PlayerOptions`, `Source`, `StateChange`, `useAn1Player`.

## React 18

On React 18, function components can't receive `ref` as a prop, so the `ref` prop is ignored. Keep the player from `onReady` instead:

```tsx
const [player, setPlayer] = useState<An1PlayerHandle | null>(null)
<An1Player game="/an1mbyt3/game.teab" onReady={setPlayer} style={{ height: 400 }} />
<button disabled={!player} onClick={() => player?.pause()}>Pause</button>
```

The handle is destroyed when the component unmounts or `game` changes, so if `game` can change, also clear it (`setPlayer(null)`) when you change `game`. All the other props work the same on 18 and 19.

## StrictMode, unmounting and remounting

- **StrictMode is safe.** In development React mounts, unmounts and remounts effects; the component cancels the first load and destroys any player it already made.
- **Unmounting destroys the player**, freeing the engine and removing the canvas. Mounting again downloads the game and engine again (your browser's HTTP cache usually makes that fast).
- **Two `<An1Player>`s on one page** don't run side by side: the second to load destroys the first. Show one at a time, and use [Toasty Lite](../runtimes/lite.mdx) for animated UI around the game.
