# Recipes

Each recipe is a small, complete page pattern built around one of the two example games, [Toast Catch](../games/toast-catch.mdx) (data `speed`; Properties `score` and `lives`; events `score` and `gameover`) and [Hop](../games/hop.mdx) (Property `score`; event `gameover` with `{ score, best }`). The live blocks are editable; click a game to run it. To use one in your own app, swap `ToastyPlayer` for `An1Player` from `./an1mbyt3/an1mbyt3-react.js` and point `game` at your export.

## Leaderboard with a name field

The page owns the leaderboard. When a round ends, the score is saved under the name in the field. The "server" here is a stand-in with a short delay; replace `saveScore` with your API call.

```jsx live
function Leaderboard() {
  const [name, setName] = React.useState('Maya Chen')
  const [board, setBoard] = React.useState([
    { name: 'Daniel Okafor', score: 24 },
    { name: 'Priya Raman', score: 17 },
    { name: 'Lena Fischer', score: 9 },
  ])
  const [status, setStatus] = React.useState('')
  const saveScore = (entry) => new Promise((resolve) => setTimeout(() => resolve(entry), 400))

  return (
    <div style={{ display: 'grid', gap: 12 }}>
      <label>
        Playing as{' '}
        <input value={name} onChange={(e) => setName(e.target.value)} maxLength={24} />
      </label>
      <ToastyPlayer
        game="/games/toast-catch.teab"
        keyboard="focus"
        style={{ height: 300 }}
        onEvent={async (e) => {
          if (e.name !== 'gameover') return
          setStatus('Saving…')
          const saved = await saveScore({ name: name.trim() || 'Anonymous', score: e.payload.score })
          setBoard((b) => [...b, saved].sort((x, y) => y.score - x.score).slice(0, 5))
          setStatus('Saved ' + saved.score + ' for ' + saved.name + '.')
        }}
      />
      <ol style={{ margin: 0 }}>
        {board.map((row, i) => <li key={i}>{row.name}: {row.score}</li>)}
      </ol>
      <small>{status}</small>
    </div>
  )
}
```

The name field sits on the same page as a game that listens to the keyboard. That works because `keyboard="focus"` (the default) only sends keys to the game while its canvas has focus. Typing in the field doesn't move the plate, and clicking the game gives it the keys back.

## Remember the visitor's settings

A settings panel that saves to `localStorage` on the page side and sends the value to the game as data. Reload the page and the difficulty is still selected.

```jsx live
function SavedDifficulty() {
  const key = 'northwind.arcade.speed'
  const [speed, setSpeed] = React.useState(() => {
    try { return Number(localStorage.getItem(key)) || 1 } catch { return 1 }
  })
  const choose = (value) => {
    setSpeed(value)
    try { localStorage.setItem(key, String(value)) } catch {}
  }
  return (
    <div>
      <fieldset style={{ display: 'flex', gap: 12, border: 0, padding: 0, marginBottom: 8 }}>
        <legend style={{ marginBottom: 4 }}>Difficulty</legend>
        {[['Relaxed', 0.7], ['Normal', 1], ['Hectic', 1.6]].map(([label, value]) => (
          <label key={label}>
            <input type="radio" name="difficulty" checked={speed === value} onChange={() => choose(value)} /> {label}
          </label>
        ))}
      </fieldset>
      <ToastyPlayer game="/games/toast-catch.teab" data={{ speed }} style={{ height: 300 }} />
    </div>
  )
}
```

Page settings belong in the page's storage. Things the game itself must remember, like Hop's best score, belong in [`ctx.storage`](../scripting/storage-api.mdx).

## Share a score, with a Lite copy button

The game runs on the engine; the button next to it is a [Toasty Lite](../runtimes/lite.mdx) `copy` icon. They run side by side because Lite doesn't count toward the one-engine-per-page limit. After a run of Hop, click the icon to copy the result.

```jsx live
function ShareRun() {
  const [result, setResult] = React.useState(null)
  const [note, setNote] = React.useState('Finish a run to share it.')
  const copy = async () => {
    if (!result) return
    const text = 'I hopped ' + result.score + ' in Hop (best ' + result.best + ').'
    try {
      await navigator.clipboard.writeText(text)
      setNote('Copied: ' + text)
    } catch {
      setNote(text)
    }
  }
  return (
    <div>
      <ToastyPlayer
        game="/games/hop.teab"
        style={{ height: 240 }}
        onEvent={(e) => {
          if (e.name !== 'gameover') return
          setResult(e.payload)
          setNote('Run over: ' + e.payload.score + '. Copy your result.')
        }}
      />
      <div style={{ display: 'flex', alignItems: 'center', gap: 8, marginTop: 8 }}>
        <Lite src="copy" ink="auto" label="Copy result" style={{ width: 36, height: 36, opacity: result ? 1 : 0.4 }}
          onEvent={(e) => e.name === 'copy' && copy()} />
        <span>{note}</span>
      </div>
    </div>
  )
}
```

The `copy` component fires its own check-mark animation on click and sends a `copy` event; the page does the actual copying. See [Copy to clipboard](../use-cases/copy-to-clipboard.mdx) for the component on its own.

## An event log for debugging

Drop this next to any game while you build the page. It shows everything the game says.

```jsx live
function EventLog() {
  const [lines, setLines] = React.useState([])
  const add = (kind, value) => setLines((l) => [kind.padEnd(6) + ' ' + JSON.stringify(value), ...l].slice(0, 12))
  return (
    <div>
      <ToastyPlayer
        game="/games/toast-catch.teab"
        style={{ height: 300 }}
        onReady={(p) => add('ready', { scenes: p.scenes, scene: p.scene, state: p.state })}
        onEvent={(e) => add('event', e)}
        onStateChange={(e) => add('state', e)}
        onPropChange={(e) => add('prop', e)}
        onSceneChange={(e) => add('scene', e)}
        onError={(err) => add('error', String(err))}
      />
      <pre style={{ fontSize: 12, minHeight: 160 }}>{lines.join('\n')}</pre>
    </div>
  )
}
```

The exported `example.html` does the same with plain JavaScript.

## Pause when off screen

A game nobody can see shouldn't keep running. An `IntersectionObserver` on a wrapper drives `paused`. Start the game, scroll it out of view and back.

```jsx live
function PauseOffscreen() {
  const box = React.useRef(null)
  const [visible, setVisible] = React.useState(true)
  React.useEffect(() => {
    const io = new IntersectionObserver(([entry]) => setVisible(entry.isIntersecting), { threshold: 0.1 })
    io.observe(box.current)
    return () => io.disconnect()
  }, [])
  return (
    <div ref={box}>
      <ToastyPlayer game="/games/hop.teab" paused={!visible} style={{ height: 240 }} />
      <small>{visible ? 'Playing' : 'Paused (off screen)'}</small>
    </div>
  )
}
```

Add `document.visibilityState` if you also want to pause in background tabs (see the [React page](./react.mdx#pausing-paused)).

## Respect reduced motion

```tsx
const reduce = window.matchMedia('(prefers-reduced-motion: reduce)').matches
<An1Player game="/an1mbyt3/game.teab" paused={reduce} style={{ height: 360 }} />
```

For a game, starting paused behind a clear "Play" button is usually better than not showing it at all. You can also send the preference as data (`data={{ reducedMotion: reduce }}`) and have the script tone down screen shake and spinning, as Toast Catch could with its slice spin.

## Load only when needed

The engine is the big download. Start it only when the box gets near the viewport, and show a [Toasty Lite](../runtimes/html.mdx) loader while it loads:

```html
<div id="game" style="height: 360px; display: grid; place-items: center">
  <toasty-lite src="/toasty/lite/loader.json" ink="currentColor" style="width: 48px; height: 48px"></toasty-lite>
</div>

<script type="module" src="/toasty/an1mbyt3-lite.js"></script>
<script type="module">
  import { createPlayer } from '/an1mbyt3/an1mbyt3-embed.js'

  const box = document.getElementById('game')
  const io = new IntersectionObserver(async ([entry]) => {
    if (!entry.isIntersecting) return
    io.disconnect()
    const player = await createPlayer(box, { game: '/an1mbyt3/game.teab' })
    box.querySelector('toasty-lite')?.remove()
    player.on('event', ({ name, payload }) => console.log(name, payload))
  }, { rootMargin: '300px' })
  io.observe(box)
</script>
```

In React, render `<An1Player>` only once a similar observer says the box is near (`{near && <An1Player … />}`). Or wait for a click on a poster image, which is what the live examples in these docs do.

## Analytics from game events

```js
player.on('event', ({ name, payload }) => analytics.track('game_' + name, payload))
player.on('scene', ({ scene }) => analytics.page('game/' + scene))
```

Because the DOM events bubble, an analytics module that never sees the player object can listen on `document` instead:

```js
document.addEventListener('an1:event', (e) => analytics.track('game_' + e.detail.name, e.detail.payload))
```

## Several games, one page

Only one engine player runs per page. To offer several games, show one at a time (tabs, a modal, a "Now playing" slot) and mount only the visible one. Changing the `game` prop swaps the game in the same box:

```tsx
const games = { 'Toast Catch': '/an1mbyt3/toast-catch.teab', Hop: '/an1mbyt3/hop.teab' }
const [tab, setTab] = useState<keyof typeof games>('Toast Catch')

<nav>{Object.keys(games).map((g) => <button key={g} onClick={() => setTab(g as keyof typeof games)}>{g}</button>)}</nav>
<An1Player game={games[tab]} wasm="/an1mbyt3/an1mbyt3_wasm_bg.wasm" style={{ height: 360 }} />
```

Both games can share one copy of the engine. The player looks for `an1mbyt3_wasm_bg.wasm` in the same folder as the `.teab`, so with both files in `/an1mbyt3/` the `wasm` prop is optional; pass it when the games live in different folders. The live version is on the [React page](./react.mdx#swapping-games-game). Everything else on the page that animates (icons, buttons, loaders) can be [Toasty Lite](../runtimes/lite.mdx), which has no per-page limit.
