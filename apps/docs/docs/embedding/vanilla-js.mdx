# Plain JavaScript, Vue and Svelte

`createPlayer` from `an1mbyt3-embed.js` works in any page that runs JavaScript modules. It is what the React component and the `<an1-player>` tag use underneath, so everything they can do, it can do.

## Start a player

```html
<div id="game" style="width: 100%; height: 400px"></div>

<script type="module">
  import { createPlayer } from './an1mbyt3/an1mbyt3-embed.js'

  const player = await createPlayer(document.getElementById('game'), {
    game: '/an1mbyt3/game.teab',
  })
</script>
```

`createPlayer(container, options)` returns a promise. It downloads the engine and the game in parallel, starts the engine, opens the first scene (or `options.scene`), and resolves with the **player** once that scene is running.

The container is yours: any element with a size. The player adds its canvas inside it (centred, letterboxed), sets `overflow: hidden` on it, and sets `position: relative` if it was `static`.

### Options

```js
const player = await createPlayer(container, {
  game: '/an1mbyt3/game.teab',       // required: URL, URL object, ArrayBuffer or Uint8Array
  wasm: '/an1mbyt3/an1mbyt3_wasm_bg.wasm', // default: next to `game` (required when `game` is bytes)
  scene: 'Like',                     // start scene by name; default: the first scene
  fit: 'contain',                    // 'contain' (letterbox, default) or 'cover' (fill + crop)
  keyboard: 'focus',                 // 'focus' (default), 'window' or 'none'
  data: { count: 128, liked: false },// starting data, same as calling set() for each
  paused: false,                     // start paused
  background: '#0b0d12',             // letterbox colour; default transparent
  stats: false,                      // frame profiler overlay; F3 or ` toggles it too
})
```

Every option is described in the [API reference](./api-reference.mdx#createplayer-options).

## Control it

```js
player.set('count', 200)                   // data: ctx.data.count + Property "count"
player.setData({ count: 200, liked: true }) // several at once
player.get('count')                        // the Property's current value

player.setInput('isNight', true)           // Bool / Number / Enum input
player.fire('burst')                       // a Trigger
player.loadScene('House')                  // switch scene after this frame
player.call('reset', { level: 1 })         // a function the game registered with ctx.on

player.pause()
player.play()
player.destroy()                           // stop, remove the canvas, free the engine
```

And read where it is:

```js
player.scenes       // ['Village', 'House']
player.scene        // 'Village'
player.state        // base layer's current state, e.g. 'Idle' (null without a state machine)
player.layerStates  // { Eyes: 'Blink', … } for extra state machine layers
player.paused       // true / false
player.canvas       // the <canvas>
player.container    // the element you passed in
```

Here is the same player object driven live. In React the docs' `ToastyPlayer` exposes it through `ref`, but the methods are exactly the ones `createPlayer` returns:

```jsx live
function PlayerObject() {
  const ref = React.useRef(null)
  const [out, setOut] = React.useState('click the card to start, then try the buttons')
  const show = (label, value) => setOut(`${label} → ${JSON.stringify(value)}`)
  const p = () => ref.current
  return (
    <div>
      <ToastyPlayer ref={ref} game="/games/like-button.teab" style={{ height: 220 }} />
      <div style={{ display: 'flex', gap: 6, flexWrap: 'wrap', marginTop: 8 }}>
        <button onClick={() => p()?.set('count', Math.floor(Math.random() * 1000))}>set('count', random)</button>
        <button onClick={() => p()?.set('liked', !p()?.get('liked'))}>toggle 'liked'</button>
        <button onClick={() => show("get('count')", p()?.get('count'))}>get('count')</button>
        <button onClick={() => p()?.fire('burst')}>fire('burst')</button>
        <button onClick={() => show('state', p()?.state)}>state</button>
        <button onClick={() => show('scenes', p()?.scenes)}>scenes</button>
        <button onClick={() => (p()?.paused ? p()?.play() : p()?.pause())}>pause / play</button>
      </div>
      <pre style={{ marginTop: 8 }}>{out}</pre>
    </div>
  )
}
```

## Listen to it

```js
const off = player.on('event', ({ name, payload }) => {
  if (name === 'like') console.log('now', payload.count)
})
player.on('state', ({ layer, state, previous }) => console.log(layer ?? 'base', previous, '→', state))
player.on('prop', ({ name, value }) => console.log('game set', name, value))
player.on('scene', ({ scene, previous }) => console.log('scene', previous, '→', scene))
player.on('error', ({ error }) => console.error(error))

off()                        // on() returns an unsubscribe function
player.off('event', handler) // or remove a named handler

await player.waitForState('Liked')  // resolves when the base layer is in 'Liked'
```

The starting state is not sent as a `state` event; read `player.state` right after `createPlayer` resolves, then subscribe. More in [Listening to the game](./listening.mdx).

### DOM events

Every player event is also dispatched as a DOM `CustomEvent` named `an1:<type>` on the container, with the payload in `detail`. Handy when another part of your page, which doesn't hold the player object, wants to know:

```js
const box = document.getElementById('game')
box.addEventListener('an1:state', (e) => console.log(e.detail.state))
box.addEventListener('an1:event', (e) => console.log(e.detail.name, e.detail.payload))
```

These events don't bubble, so listen on the container itself. `an1:ready` is dispatched before `createPlayer` resolves, so add that listener *before* calling `createPlayer`.

## Loading and errors

`createPlayer` rejects if it can't start:

```js
try {
  const player = await createPlayer(box, { game: '/an1mbyt3/game.teab' })
} catch (err) {
  box.textContent = 'The animation could not load.'
  console.error(err) // e.g. "couldn't load /an1mbyt3/game.teab (404)"
}
```

Show a placeholder while it loads (the engine is the big part of the download), for example a CSS background on the container or a spinner you remove after `await`.

After it starts, a frame that throws is skipped and reported through `on('error')`; the game keeps running.

## Clean up

Call `player.destroy()` when the game's box goes away (route change, modal closed). It stops the frame loop, removes the canvas and the HTML overlay, releases held keys and frees the engine's memory. Calling it twice is harmless.

Only one player runs per page: calling `createPlayer` again destroys the previous player automatically. To swap games, just create the new one.

## Vue 3

```vue title="ToastyGame.vue"
<script setup lang="ts">
import { onMounted, onBeforeUnmount, ref, watch } from 'vue'
import { createPlayer, type An1Player } from './an1mbyt3/an1mbyt3-embed.js'

const props = defineProps<{ count: number }>()
const emit = defineEmits<{ like: [count: number] }>()
const box = ref<HTMLDivElement | null>(null)
let player: An1Player | null = null
let cancelled = false

onMounted(async () => {
  const p = await createPlayer(box.value!, { game: '/an1mbyt3/game.teab', data: { count: props.count } })
  if (cancelled) return p.destroy()
  player = p
  player.on('event', (e) => {
    if (e.name === 'like') emit('like', (e.payload as { count: number }).count)
  })
})

// Props → game. set() is cheap; call it on every change.
watch(() => props.count, (count) => player?.set('count', count))

onBeforeUnmount(() => {
  cancelled = true
  player?.destroy()
})
</script>

<template>
  <div ref="box" style="height: 320px" />
</template>
```

In Nuxt, wrap it in `<ClientOnly>` (the player can't run on the server).

## Svelte 5

```svelte title="ToastyGame.svelte"
<script lang="ts">
  import { onMount } from 'svelte'
  import { createPlayer, type An1Player } from './an1mbyt3/an1mbyt3-embed.js'

  let { count = 128, onlike = (n: number) => {} } = $props()
  let box: HTMLDivElement
  let player: An1Player | null = $state(null)

  onMount(() => {
    let cancelled = false
    createPlayer(box, { game: '/an1mbyt3/game.teab', data: { count } }).then((p) => {
      if (cancelled) return p.destroy()
      player = p
      p.on('event', (e) => e.name === 'like' && onlike((e.payload as { count: number }).count))
    })
    return () => {
      cancelled = true
      player?.destroy()
    }
  })

  // Re-runs whenever `count` (or `player`) changes.
  $effect(() => {
    player?.set('count', count)
  })
</script>

<div bind:this={box} style="height: 320px"></div>
<button disabled={!player} onclick={() => player?.fire('burst')}>Burst</button>
```

`onMount` never runs during SvelteKit's server rendering, so no extra guard is needed.

## Angular

```ts title="toasty-game.component.ts"
import { Component, ElementRef, Input, OnChanges, OnDestroy, AfterViewInit, ViewChild } from '@angular/core'
import { createPlayer, type An1Player } from './an1mbyt3/an1mbyt3-embed.js'

@Component({
  selector: 'toasty-game',
  standalone: true,
  template: `<div #box style="height: 320px"></div>`,
})
export class ToastyGameComponent implements AfterViewInit, OnChanges, OnDestroy {
  @ViewChild('box') box!: ElementRef<HTMLDivElement>
  @Input() count = 128
  private player: An1Player | null = null
  private destroyed = false

  async ngAfterViewInit() {
    const p = await createPlayer(this.box.nativeElement, { game: '/an1mbyt3/game.teab', data: { count: this.count } })
    if (this.destroyed) return p.destroy()
    this.player = p
  }
  ngOnChanges() {
    this.player?.set('count', this.count)
  }
  ngOnDestroy() {
    this.destroyed = true
    this.player?.destroy()
  }
}
```

Or use the [custom element](./custom-element.mdx), which needs no component wrapper at all.
